1. 导读与背景

点击率（CTR, Click-Through Rate）预估是推荐系统和在线广告的核心任务：给定一个用户和候选物品（或广告），模型需要预测用户点击它的概率。

在在线广告中，系统通常按预估 CTR $\times$ bid 排序所有候选，因此 CTR 的准确性直接影响平台收入。在推荐系统中，准确的 CTR 预估意味着用户更可能看到自己感兴趣的物品。

关键洞察： 用户行为背后的特征交互（feature interactions）是复杂的，低阶交互（如"用餐时间 → 餐饮类 App"）和高阶交互（如"年轻男性 ∧ 游戏 App ∧ 周末"）都对 CTR 有贡献。

2. 动机：为什么需要 DeepFM？

论文以 App 商店的用户行为为例：

  • 低阶交互（order-2）： 用户在用餐时间倾向于下载外卖 App——App 类别与时间戳的二阶交互是一个重要信号
  • 高阶交互（order-3）： 年轻男性喜欢射击类和 RPG 游戏——App 类别 $\times$ 用户性别 $\times$ 年龄的三阶交互是另一个信号

多数特征交互隐藏在数据中，专家无法穷举设计（如经典的"啤酒与尿布"关联规则来自数据挖掘，而非专家经验）。

核心挑战： 如何自动地、端到端地同时学习低阶和高阶特征交互，且无需任何特征工程？

3. 现有方法的局限

LR (Logistic Regression / FTRL)

线性模型，表达能力有限。虽然可以手动加入交叉特征，但无法泛化到未在训练数据中出现的特征组合，更无法建模高阶交互。

FM (Factorization Machines)

用隐向量内积建模二阶特征交互。在稀疏数据下效果显著，但实践中仅考虑 order-2 交互（高阶复杂度太高）。

FNN (FM-initialized Neural Network)

先预训练 FM，再用 FM 的隐向量初始化 DNN。局限：① 预训练使 embedding 偏向 FM；② 需要额外预训练阶段；③ 只捕获高阶交互，忽略低阶交互。

PNN (Product-based Neural Network)

在 embedding 层与全连接层之间引入 product layer。局限：① 内积/外积操作计算复杂度高；② 同样忽略低阶交互。

Wide & Deep (Google, 2016)

结合线性模型（Wide）和 DNN（Deep）。局限：Wide 部分需要人工设计交叉特征，依赖于特征工程。

4. 问题定义

数据集包含 $n$ 个样本 $(\chi, y)$：

  • $\chi$ 是一个 $m$ 个 field 的记录（用户 + 物品 + 上下文），$y \in \{0,1\}$ 是点击标签
  • 每个 field 可以是类别型（one-hot 编码）或连续型（直接取值或离散化后编码）
  • 所有 field 拼接后得到 $x \in \mathbb{R}^d$，$d$ 极大且极度稀疏
$$x = [x_{\text{field}_1}, x_{\text{field}_2}, \dots, x_{\text{field}_m}], \quad x \in \mathbb{R}^d$$

目标是学习一个预测模型 $\hat{y} = \text{CTR model}(x)$，估计用户点击的概率。

记号约定：
  • $i$：特征维度编号，$i \in \{1, 2, \dots, d\}$
  • $j$：field 编号，$j \in \{1, 2, \dots, m\}$
  • $w_i$：特征 $i$ 的一阶权重（标量）
  • $V_i \in \mathbb{R}^k$：特征 $i$ 的隐向量（embedding），$k$ 为 embedding 维度

5. DeepFM 架构总览

图 1：DeepFM 架构。FM component 和 Deep component 共享同一输入和同一套 embedding 向量。
$$\hat{y} = \sigma(y_{\text{FM}} + y_{\text{DNN}}), \quad \sigma(x) = \frac{1}{1 + e^{-x}}$$

对于每个特征 $i$：

  • 标量 $w_i$：衡量一阶重要性
  • 隐向量 $V_i \in \mathbb{R}^k$：衡量与其他特征的交互影响
  • $V_i$ 同时输入 FM component（建模 order-2）和 Deep component（通过 embedding 喂养 DNN，建模高阶交互）

6. FM Component — 低阶特征交互

i ... xd Addition: $\sum w_i x_i$ Inner Product: $\sum V_i V_j$ $y_{FM} = $ (1) + (2) to Sigmoid FM 组件：一阶线性项 + 二阶交互项
图 2：FM Component 架构（论文 Figure 2）。
$$y_{\text{FM}} = \underbrace{\langle w, x \rangle}_{\text{order-1}} + \underbrace{\sum_{j_1=1}^{d} \sum_{j_2=j_1+1}^{d} \langle V_{j_1}, V_{j_2} \rangle x_{j_1} \cdot x_{j_2}}_{\text{order-2 pairwise interactions}}$$

其中 $w \in \mathbb{R}^d$，$V_i \in \mathbb{R}^k$（$k$ 为 embedding 维度）。

为什么 FM 在稀疏数据下有效？

传统方法中，特征 $i$ 和 $j$ 的交互权重 $\hat{w}_{ij}$ 需要同时出现在同一条样本中才能被训练。而 FM 通过隐向量内积 $\langle V_i, V_j \rangle$ 来建模交互——只要 $i$ 或 $j$ 各自出现在训练样本中，$V_i$ 和 $V_j$ 就能被训练。因此，从未出现（或极少出现）的特征组合也能被更好地学习。

FM 的核心优势： 参数共享。每个特征的隐向量 $V_i$ 被所有包含该特征的交互对共享，使模型可以泛化到未见过的特征组合。

FM 计算优化

FM 的二阶项可以化简为 $O(dk)$ 而非 $O(d^2k)$：

$$\sum_{j_1=1}^{d} \sum_{j_2=j_1+1}^{d} \langle V_{j_1}, V_{j_2} \rangle x_{j_1} x_{j_2} = \frac{1}{2} \sum_{f=1}^{k} \left[ \left( \sum_{j=1}^{d} v_{j,f} x_j \right)^2 - \sum_{j=1}^{d} v_{j,f}^2 x_j^2 \right]$$

7. Deep Component — 高阶特征交互

图 3：Deep Component（论文 Figure 3 & 4）。先通过 embedding 层将超高维稀疏向量压缩为每个 field 的稠密向量，再送入全连接网络。

前向过程：

$$a^{(0)} = [e_1, e_2, \dots, e_m]$$ $$a^{(l+1)} = \sigma(W^{(l)} a^{(l)} + b^{(l)})$$ $$y_{\text{DNN}} = \sigma(W^{(|H|+1)} \cdot a^{(|H|)} + b^{(|H|+1)})$$

其中 $e_j \in \mathbb{R}^k$ 是第 $j$ 个 field 的 embedding，$|H|$ 是隐藏层数，$\sigma$ 是激活函数（通常用 ReLU 或 tanh）。

8. 共享 Embedding 的设计

DeepFM 的关键创新：FM component 和 Deep component 共享同一套特征 embedding。具体来说：

  • 每个特征 $i$ 的隐向量 $V_i$ 既是 FM 中二阶交互的表示，也是 Deep 部分中该特征 field 的 embedding 向量
  • 在反向传播时，梯度会同时从 FM component 和 Deep component 流向共享的 $V_i$

共享 Embedding 的两大好处

  1. 同时学习低阶和高阶交互： FM 的梯度使 embedding 捕捉低阶交互模式，DNN 的梯度使 embedding 捕捉高阶交互模式，两者互相增强
  2. 无需特征工程： 与 Wide & Deep 不同，DeepFM 不需要为 Wide 部分单独设计交叉特征（如 "installed app × impression app"）
与 Wide & Deep 的关键区别：
  • Wide & Deep 的 Wide 部分（LR）需要人工设计交叉特征，输入向量维度巨大
  • DeepFM 的 FM 部分自动学习二阶交叉，且与 Deep 部分共享 embedding，无需任何人工特征

9. 与 FNN / PNN / Wide & Deep 的详细对比

FNN (Factorization-machine supported Neural Network)

FNN 先预训练 FM，再用 FM 隐向量初始化 DNN 的 embedding 层。问题：

  • 预训练阶段开销大，且 embedding 受 FM 主导
  • 只有 DNN（高阶）部分，没有 FM 式的低阶交互——FNN 只捕获高阶交互

PNN (Product-based Neural Network)

PNN 在 embedding 层和第一个隐藏层之间引入 product layer。有三种变体：

  • IPNN： 基于内积（inner product）
  • OPNN： 基于外积（outer product），但外积近似计算丢失信息，结果不稳定
  • PNN*： 同时使用内积和外积

PNN 的 product layer 输出连接到第一隐藏层的所有神经元，计算复杂度高。而 DeepFM 的 FM 输出只连接到最终的输出层（一个神经元）。

Wide & Deep (Google, 2016)

Wide 部分（LR）需要人工设计交叉特征；Deep 部分（DNN）学习高阶交互。两个部分的输入不同，未共享 embedding。

论文还评估了两种 Wide & Deep 的变体：

  • LR & DNN： 原始 Wide & Deep，用 LR 做 Wide 部分
  • FM & DNN： 用 FM 替换 LR 作为 Wide 部分（与 DeepFM 表面相似，但 FM 与 DNN 的 embedding 不共享）
DeepFM vs. FM & DNN： 两者都有 FM 和 DNN，但 DeepFM 的 FM 和 DNN 共享同一套 embedding，而 FM & DNN 使用独立的 embedding。共享策略使 embedding 同时受低阶和高阶交互的梯度影响，表示更精确。

关键发现

  1. 特征交互提升 CTR： LR（无交互）在所有模型中表现最差。DeepFM 在 Company* 上 AUC 比 LR 高 0.86%，LogLoss 低 1.15%；在 Criteo 上 AUC 高 4.18%，LogLoss 低 5.60%
  2. 同时学习低阶和高阶交互更好： DeepFM 优于只学低阶（FM）或只学高阶（FNN, PNN）的模型。在 Company* 上 AUC 比最好的第二名高 0.37%+
  3. 共享 embedding 策略有效： DeepFM 优于使用独立 embedding 的 LR&DNN 和 FM&DNN（AUC 提高 0.33%~0.48%）
离线 AUC 提升的实际意义： 据 Google Wide & Deep 论文报告，离线 AUC 提升 0.275% 对应在线 CTR 提升 3.9%。Company* App Store 日流水达数百万美元，即使几个百分点的 CTR 提升也能带来每年数百万美元的额外收入。

效率对比

论文在 CPU 和 GPU 上测量了各模型相对于 LR 的训练时间比：

  • FNN 因预训练阶段效率较低
  • IPNN 和 PNN* 的 product layer 计算复杂，即使 GPU 加速也仍然昂贵
  • DeepFM 在 CPU 和 GPU 上都是最高效的模型之一

11. 超参数研究

论文在 Company* 数据集上对 5 个超参数进行了系统研究：

① 激活函数

对比 ReLU 和 tanh：

  • 大多数模型（除 IPNN 外）使用 ReLU 效果更好
  • 可能原因：ReLU 引入稀疏性，有助于防止过拟合

② Dropout 率

测试范围：[1.0, 0.9, 0.8, 0.7, 0.6, 0.5]（数值表示 keep probability）

  • 所有模型在 0.6~0.9 范围内达到最佳性能
  • 适当的随机性增强了模型鲁棒性

③ 每层神经元数

  • 在 Company* 上，200 或 400 个神经元是好的选择
  • 从 400 增加到 800 并不持续提升——模型过于复杂容易过拟合

④ 隐藏层数

  • 增加层数初期提升性能，但继续增加后性能下降
  • 原因仍然是过拟合

⑤ 网络形状

保持总神经元数和层数不变，测试四种形状：

  • Constant（200-200-200）：最佳
  • Increasing（100-200-300）
  • Decreasing（300-200-100）
  • Diamond（150-300-150）

Constant 形状经验上最好，与之前的研究（Larochelle et al., 2009）一致。

12. PyTorch 风格伪代码

import torch
import torch.nn as nn

class DeepFM(nn.Module):
    def __init__(self, d, k, field_sizes, hidden_dims, dropout=0.5):
        """
        d              : total number of features (sparse dimension)
        k              : embedding dimension
        field_sizes    : list of vocab sizes per field, e.g. [10000, 500, 2, ...]
        hidden_dims    : list of hidden layer sizes, e.g. [400, 400, 400]
        """
        super().__init__()
        # --- 一阶权重 ---
        self.w = nn.Parameter(torch.randn(d, 1) * 0.01)

        # --- 二阶隐向量 (embedding) ---
        # 每个 field 有自己的 embedding table
        self.embeddings = nn.ModuleList([
            nn.Embedding(vocab_size, k) for vocab_size in field_sizes
        ])

        # --- Deep component ---
        layers = []
        in_dim = len(field_sizes) * k
        for h in hidden_dims:
            layers.append(nn.Linear(in_dim, h))
            layers.append(nn.BatchNorm1d(h))
            layers.append(nn.ReLU())
            layers.append(nn.Dropout(dropout))
            in_dim = h
        self.deep_layers = nn.Sequential(*layers)
        self.deep_output = nn.Linear(in_dim, 1)

    def forward(self, field_indices, feature_values):
        """
        field_indices : list of LongTensor, each shape (batch,)
                        每张表索引
        feature_values: (batch, d) 稀疏特征向量中的非零值
        """
        batch_size = field_indices[0].shape[0]

        # === 一阶项 ===
        # y_linear = sum(w_i * x_i)
        # 实际实现中需将 w 参数与 feature_values 做点积
        # 这里简化: 用 embedding bag 或 gather
        y_linear = (self.w * feature_values).sum(dim=1, keepdim=True)

        # === FM 二阶项 ===
        # 先获取每个 field 的 embedding
        field_embeds = []
        for i, emb in enumerate(self.embeddings):
            field_embeds.append(emb(field_indices[i]))  # (batch, k)
        # stack: (batch, m, k)
        embs = torch.stack(field_embeds, dim=1)

        # sum_square 和 square_sum 的差
        sum_emb = embs.sum(dim=1)                     # (batch, k)
        sum_sq = sum_emb ** 2                          # (batch, k)
        sq_sum = (embs ** 2).sum(dim=1)                # (batch, k)
        y_fm = 0.5 * (sum_sq - sq_sum).sum(dim=1, keepdim=True)  # (batch, 1)

        # === Deep component ===
        deep_in = embs.reshape(batch_size, -1)         # (batch, m*k)
        deep_out = self.deep_layers(deep_in)
        y_dnn = self.deep_output(deep_out)

        # === 合并输出 ===
        y = y_linear + y_fm + y_dnn
        return torch.sigmoid(y)


# 使用示例
model = DeepFM(
    d=100000,
    k=10,
    field_sizes=[10000, 500, 20, 50, 7],
    hidden_dims=[400, 400, 400],
    dropout=0.5
)

optimizer = torch.optim.Adam(model.parameters())
criterion = nn.BCELoss()  # binary cross-entropy

for epoch in range(10):
    for batch in dataloader:
        pred = model(batch.indices, batch.values)
        loss = criterion(pred, batch.label)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

15. 结论

DeepFM 的三个核心优势

  1. 无需预训练： 端到端联合训练，避免 FNN 的预训练开销和偏差
  2. 同时学习低阶和高阶特征交互： FM component 负责低阶（order-1 + order-2），Deep component 负责高阶，两者互补
  3. 共享 embedding 避免特征工程： 不同于 Wide & Deep，DeepFM 不需要人工设计交叉特征

实验结果表明，DeepFM 在 Criteo 和 Company* 两个数据集上的一致 AUC 和 LogLoss 提升，且效率与最高效的模型相当。

未来方向（论文提出）

  • 引入池化层（pooling layer）增强学习最有用的高阶交互的能力
  • 在 GPU 集群上训练 DeepFM 以处理更大规模问题
