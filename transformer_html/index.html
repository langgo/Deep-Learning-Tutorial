它的输入是一串 token，输出是每个位置的新表示，最后可以接分类头、翻译头或下一个 token 预测头。 本教程不假设你已经会深度学习，但会保留必要数学深度。每个公式都会先说明变量从哪里来，再说明它在工程上代表什么。

初学者自检问题

  • 看到 token：我能说清它和“自然语言里的一个词”有什么不同吗？
  • 看到 embedding：我能说清它是查表得到的向量，不是人工词典释义吗？
  • 看到 attention：我能把它拆成“打分、softmax、加权求和”三步吗？
  • 看到 mask：我能说明它是在控制可见范围，而不是删除 token 吗？
  • 看到 KV cache：我能说明它缓存的是历史 key/value，不是长期记忆吗？

在 Transformer 之前，序列模型常用 RNN、LSTM、GRU 或 CNN。它们都能处理文本，但遇到长距离依赖和大规模并行训练时会吃力。

先不要急着学公式：这一章只解决一个问题

如果你是软件工程师，可以先把“理解一句话”看成“给每个词补充上下文注释”。 例如 bank 这个词本身可能是“银行”，也可能是“河岸”。只有看到周围的 money、river、deposit， 我们才知道它应该偏向哪个意思。

所以序列模型的核心问题不是“把字符串变成数字”这么简单，而是： 每个位置如何获得其他位置的信息？这些信息要走多远？能不能并行算？ Transformer 的大部分设计，都是围绕这个问题展开的。

这一章先回答“为什么要换一种结构”。 Transformer 不是因为 RNN、CNN 完全不能用才出现，而是因为在长序列、大数据和并行训练场景下，旧结构暴露了信息路径长、并行度不足和远距离依赖难建模的问题。 先理解这些限制，后面看到 self-attention 时，才知道它解决的是“上下文信息如何高效流动”的问题。

从一个软件工程类比开始

假设你在读一段代码，当前行的含义可能依赖前面的变量定义、函数参数、配置项，甚至远处的注释。 文本也是这样：一个词的含义不只由它自己决定，还由上下文中其他词决定。

RNN 的思路像顺序扫描日志：先读第 1 个 token，再读第 2 个 token，把历史压缩到一个状态里。 这很自然，但也带来两个问题：长距离信息容易被压扁，训练时很难把所有位置完全并行起来。

Transformer 的关键转向是：让每个 token 直接和其他 token 建立关系。这个机制叫 self-attention。 “self” 表示同一句内部互相看，“attention” 表示为不同 token 分配不同权重。

上下文当前位置附近或远处能帮助解释它的其他内容。attention 加权汇总出来的向量。

三种序列处理方式

图中每个圆点是一个 token。RNN 强调前后传递，CNN 强调局部窗口，self-attention 允许任意位置直接建立连接。

RNN 的信息流：一步一步传话

RNN 处理第 t 个位置时，通常依赖前一个隐藏状态 h[t-1] 和当前输入 x[t]。 它像接力传话：第 10 个 token 想使用第 1 个 token 的信息，信息要经过中间很多步才能传过来。

h[t] = f(h[t-1], x[t])
x[t]：第 t 个 token 的输入向量。
h[t-1]：前面 token 被压缩后的历史状态。
h[t]：读到当前位置后的新状态。
f：可训练的循环单元，例如 RNN、LSTM 或 GRU。

CNN 的信息流：先看局部，再叠很多层

CNN 处理文本时常用固定窗口观察相邻 token。例如窗口大小为 3 时，一个位置一开始只能看到自己和附近两个位置。 如果要看到更远的词，就需要堆叠多层卷积，让局部信息一层层扩散。

这种方式适合短语、固定搭配和局部语法结构，但对远距离依赖不够直接。 如果一句话里两个强相关的词隔得很远，CNN 需要更多层才能让它们发生间接交互。

Transformer 的核心变化：让依赖路径变短

Self-attention 对每个 token 直接计算它和其他 token 的关系强弱。 如果第 8 个 token 需要第 2 个 token 的信息，它不必等待信息一步步传过来，而是可以在同一层 attention 中直接给第 2 个 token 更高权重。

好处是长距离依赖路径变短，也更适合 GPU/TPU 并行。代价也很明确： 如果序列长度是 n，朴素 self-attention 要比较大约 n * n 对 token，长上下文时计算和显存成本会明显上升。

手工对比：一句话里远处信息怎么传

假设句子是 The book that I bought yesterday is useful，当前要理解 is 前面的主语是谁。 人类会很快跳回 book，但不同模型的信息路径不同：

  • RNN：book 的信息要经过 that -> I -> bought -> yesterday 一路传到 is，中间可能被压缩和稀释。
  • CNN：如果窗口很小，模型先看局部短语，再靠多层卷积逐步扩大可见范围。
  • Self-attention：is 可以在同一层直接给 book 更高权重，依赖路径更短。

这不是说 RNN/CNN 没价值，而是说明 Transformer 在长距离依赖和并行训练上更自然。

本章小结

  • Transformer 要解决的核心问题是：让序列中不同位置更直接、更并行地交换信息。
  • RNN 像顺序传话，CNN 像局部窗口扩散，self-attention 像每个位置直接查询其他位置。
  • 下一章会把“词”变成“向量矩阵”，因为 attention 的计算必须发生在数字向量上。

1. 文本如何进入模型：token、embedding、位置

神经网络不能直接读取字符串。它需要数字。Transformer 的第一步是把文本拆成 token，再把 token id 查表变成向量，最后加入位置信息。

先把输入想成一张表

初学者容易把“文本进入模型”想成模型直接读懂了自然语言。实际不是这样。 模型读到的是数字表：每一行代表一个 token，每一列代表一个向量维度。 后面所有 attention、FFN、LayerNorm，都是在这张表上做计算。

所以本章先不谈“理解”，只谈数据形态变化： 字符串先被切成 token，token 变成 id，id 查表得到 embedding，再加上位置编码，最终得到输入矩阵 X。

本章的依赖流： 原始字符串不能直接进神经网络，所以要先经过 文本 -> token -> token id -> embedding 向量 -> 加入位置 -> X 矩阵。 后面 attention 里的 Q、K、V 都是从这个 X 进一步线性变换得到的。

一个具体例子：从句子到数字

假设输入句子是“我喜欢苹果”。为了教学简化，分词器可能把它切成三个 token：

"我喜欢苹果" -> ["我", "喜欢", "苹果"] ["我", "喜欢", "苹果"] -> [18, 245, 931]

18、245、931 只是词表里的行号，不代表大小关系，也不是词义本身。 模型真正使用的是这些行号查出来的向量。实际大模型常用子词或字节级分词，本章用短 token 是为了看清计算。

矩阵形状先记住

如果一句话长度是 seq_len，模型维度是 d_model，输入矩阵 X 的形状就是：

X shape = [seq_len, d_model]
seq_len：当前输入里的 token 数量。
d_model：每个 token 用多少个数字表示。
X[pos]：矩阵第 pos 行，表示第 pos 个 token。
X[pos][dim]：第 pos 个 token 在第 dim 个维度上的数值。

手算一个最小输入矩阵

假设我们只有两个 token：我 和 喜欢，并且为了教学，向量只用 3 个维度。 词表和 embedding 表可以先想象成这样：

token ids: 我 -> 18, 喜欢 -> 245 embedding[18] = [0.2, 0.7, -0.1] embedding[245] = [0.6, 0.1, 0.4] position[0] = [0.0, 1.0, 0.0], position[1] = [0.8, 0.5, 0.1]

如果位置编码强度先取 0.1，那么第 0 个位置的输入向量就是：

X[0] = [0.2, 0.7, -0.1] + 0.1 * [0.0, 1.0, 0.0] = [0.2, 0.8, -0.1] X[1] = [0.6, 0.1, 0.4] + 0.1 * [0.8, 0.5, 0.1] = [0.68, 0.15, 0.41]

这一步之后，模型看到的不再是“我喜欢”三个字，而是一个 [2, 3] 的矩阵。

X[pos] = TokenEmbedding[token_id] + PositionalEncoding[pos]
token_id：分词器给每个 token 分配的整数编号。
TokenEmbedding：可学习查找表，行号是 token id，行内容是语义向量。
pos：token 在序列中的位置，从 0 开始。
X[pos]：送入第一层 Transformer block 的输入向量。

实际含义：embedding 负责“这个 token 大概表示什么”，position encoding 负责“这个 token 出现在第几个位置”。 如果没有位置，self-attention 本身看不出 “green tea” 和 “tea green” 的顺序差异。

为什么只靠 embedding 不够

Token embedding 只回答“这个 token 是什么”，不回答“它出现在什么位置”。 如果 self-attention 只看到一组 token 向量，而没有位置输入，那么它很难区分“猫追狗”和“狗追猫”这种词相同但顺序不同的句子。

位置编码不是替代语义，而是给每个 token 的向量加上一组位置标记。 加完之后，同一个 token 出现在第 0 位和第 5 位，会得到不同的输入向量。 这样后续 attention 在计算关系时，既能利用 token 含义，也能利用顺序信息。

检查一下：如果没有位置会怎样？

假设模型只拿到 猫、追、狗 三个 token 的 embedding，但没有任何位置标记。 那么“猫追狗”和“狗追猫”在模型看来会非常接近，因为 token 集合一样。 位置编码的作用，就是让模型知道谁在前、谁在后。

位置编码曲线

原始论文使用正弦和余弦函数。不同维度有不同频率，因此模型能从组合后的数字里分辨绝对位置和相对距离。

PE(pos, 2i) = sin(pos / 10000^(2i / d_model)) PE(pos, 2i + 1) = cos(pos / 10000^(2i / d_model))
pos：当前位置。
i：维度对的编号。
d_model：模型向量维度。
sin/cos：让位置形成周期性、可外推的数值模式。

这两个公式可以拆成三层理解：pos 说明 token 靠前还是靠后；i 决定当前维度使用快变化还是慢变化的波形； sin 和 cos 让不同位置产生可区分的数值模式。 可以把位置编码想象成“给每个座位贴一组坐标标签”。

本章小结

  • Transformer 不直接处理字符串，而是处理 X: [seq_len, d_model] 这样的矩阵。
  • Embedding 负责“这个 token 是什么”，position encoding 负责“它在什么位置”。
  • 下一章会从 X 出发，生成 Q、K、V，再计算 attention。

2. Attention 的计算：当前 token 应该看谁

Attention 不是一个神秘模块，它就是“打分、归一化、加权求和”。当前 token 先拿自己的 query 去匹配所有 token 的 key，再用匹配权重汇总 value。

先用图书馆查资料来理解 attention

你手里有一个问题，比如“Transformer 为什么能处理长距离依赖？”。图书馆里每本书都有目录标签，也有正文内容。 你会先用问题去匹配目录标签，觉得哪本书相关，就多读那本书的正文。

Attention 做的事情非常类似：当前 token 带着一个 Query 去匹配所有 token 的 Key， 匹配得分越高，就越多读取那个 token 的 Value。所以先别把它想成“注意力很玄”， 它更像一套可训练的、可微分的“查资料和摘笔记”机制。

本章的依赖流： 第 1 章得到输入矩阵 X。Attention 不直接在原始文本上计算，而是先把 X 投影成三组向量： Q 用来提问，K 用来被匹配，V 用来提供内容。 然后按 打分 -> softmax -> 加权求和 三步生成新的上下文表示。
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k)) V score_ij = q_i · k_j / sqrt(d_k) weight_ij = softmax(score_i)_j context_i = sum_j weight_ij * v_j
i：正在更新的 token 位置。
j：被查看的 token 位置。
q_i：第 i 个 token 的 query，表示“我想找什么信息”。
k_j：第 j 个 token 的 key，表示“我有什么索引特征”。
v_j：第 j 个 token 的 value，表示“如果你关注我，能拿走什么内容”。
sqrt(d_k)：缩放因子，避免维度变大后点积过大，softmax 过早变尖。

实际含义：如果 q_i 和 k_j 方向接近，点积大，softmax 权重高，第 i 个 token 就会更多吸收第 j 个 token 的 value。

Q/K/V 从哪里来

真实模型里，Q、K、V 通常不是手工指定的，而是由输入矩阵 X 乘上可训练矩阵得到。

Q = XW^Q, K = XW^K, V = XW^V
X：上一章得到的 token 输入矩阵。
W^Q：把 token 表示变成 query 的投影矩阵。
W^K：把 token 表示变成 key 的投影矩阵。
W^V：把 token 表示变成 value 的投影矩阵。

把 attention 拆成三步

  • 打分：当前位置 i 的 query 和每个位置 j 的 key 做点积。
  • 归一化：一行分数经过 softmax 变成非负权重，并且总和为 1。
  • 加权求和：用权重混合所有 value，得到第 i 个 token 的上下文向量。

一个可手算的小例子

假设当前 token 是“喜欢”，它要决定该看向“我”“喜欢”“苹果”多少。缩放后的分数是：

score = [0.2, 0.5, 1.3] softmax(score) ≈ [0.19, 0.26, 0.55] context_喜欢 ≈ 0.19 * v_我 + 0.26 * v_喜欢 + 0.55 * v_苹果

这表示“喜欢”会从三个 token 的 value 里取信息，其中“苹果”的权重大约是 0.55，贡献最大。

为什么除以 sqrt(d_k)

如果 key/query 的维度 d_k 很大，点积更容易得到较大的绝对值。 分数过大时，softmax 会变得非常尖锐，最大分数对应的 token 权重接近 1，其他 token 权重接近 0。

除以 sqrt(d_k) 是为了把分数控制在更合适的范围，让训练早期的信息混合和梯度更稳定。

继续手算：把 value 真正混合起来

前面我们只看到了权重。现在假设三个 token 的 value 都是二维向量，这样可以手算最终输出：

v_我 = [1, 0] v_喜欢 = [0, 1] v_苹果 = [2, 1] context_喜欢 = 0.19 * [1,0] + 0.26 * [0,1] + 0.55 * [2,1] context_喜欢 ≈ [1.29, 0.81]

这个 context_喜欢 已经不再只是“喜欢”这个词本身，而是“在我喜欢苹果这句话里的喜欢”。 它混入了“我”和“苹果”的信息，这就是 attention 更新 token 表示的核心。

自测：key 和 value 有什么区别？

Key 用来被 query 匹配，决定“该不该看我”；Value 是真正被加权求和拿走的内容。 如果你能说清这句话，就已经越过了 attention 最常见的理解障碍。

3. Multi-Head Attention：并行看不同关系

单个 attention 头只有一套 Q/K/V 投影，容易偏向一种关系。多头机制让模型并行学习多种“看上下文的方式”，最后把结果拼接再变换。

先后依赖： 多头 attention 不是新的 attention 公式，而是把第 2 章的“打分、softmax、加权求和”复制多份。 每一份 head 使用不同的 W^Q/W^K/W^V，因此同一个 token 会被投影到不同的关系空间里。

先用“多个读者”理解 multi-head

同一句话可以从不同角度读。语法老师可能关注主谓宾，翻译人员可能关注词义，编辑可能关注相邻短语，推理人员可能关注远处指代。 如果只让一个读者做笔记，他需要把所有关系都挤在同一份笔记里；如果让多个读者并行做笔记，每个人可以专注一种关系。

Multi-head attention 就是这种思想：同一个输入 X 被投影到多个不同的 Q/K/V 空间里， 每个 head 独立做一遍 attention，最后把结果拼接起来，再用 W^O 学习如何综合。

head_m = Attention(XW_m^Q, XW_m^K, XW_m^V) MultiHead(X) = Concat(head_1, ..., head_h) W^O
X：上一章得到的输入矩阵，每一行对应一个 token。
W_m^Q/W_m^K/W_m^V：第 m 个 head 自己的投影矩阵。
head_m：第 m 个 head 产生的上下文向量。
W^O：输出投影，把拼接后的多头结果混合回模型维度。

为什么一个 head 不够

单头 attention 只能用一套 query/key/value 解释上下文，容易把多个任务挤在同一个空间里： 有时要找主谓关系，有时要找指代关系，有时要找相邻词搭配，有时要找长距离依赖。

多头机制的实际意义是“分工”。一个 head 可以关注局部否定，例如 not good； 另一个 head 可以关注远处实体，例如 The animal ... it 中 it 指向谁。

维度如何变化

X: [seq_len, d_model] W_m^Q/W_m^K/W_m^V: [d_model, d_head] Concat(head_1, ..., head_h): [seq_len, h * d_head]
h：head 数量。
d_head：每个 head 内部使用的维度。
d_model：主模型维度。
W^O：把拼接结果混合回模型维度。

Head 1 语义关系: [我, 喜欢, 苹果] -> [0.15, 0.25, 0.60] Head 2 位置关系: [我, 喜欢, 苹果] -> [0.30, 0.50, 0.20]

4. Transformer Block：把 attention 放进可训练层

Attention 只是 Transformer block 的核心之一。一个标准 block 还包含残差连接、层归一化和前馈网络。它们共同让深层模型更稳定。

先把 block 想成“一轮阅读和加工”

第 2、3 章讲的 attention 负责“从上下文拿信息”。但拿到信息之后，模型还要保留原始词义、稳定数值范围、继续做非线性加工。 Transformer block 就是一套标准流程：先查上下文，再保留原笔记，再统一数值尺度，再逐 token 加工。

真实模型会堆叠很多个 block。浅层可能更关注局部搭配和词义消歧，深层更容易形成任务相关的抽象表示。

先后依赖： Attention 负责“从上下文取信息”，但单靠 attention 还不够。Transformer block 把 attention 包进一个可堆叠、可训练、稳定传播梯度的层结构里。
A = MultiHeadAttention(X) H = LayerNorm(X + A) F = FFN(H) = W2 * relu(W1 * H + b1) + b2 Y = LayerNorm(H + F)
X：block 输入，来自 embedding 或上一层输出。
A：attention 汇总后的上下文信息。
X + A：残差连接，保留原始信息，同时加入上下文。
LayerNorm：把每个 token 的向量拉回稳定尺度。
FFN：逐 token 的非线性变换，增强表达能力。
Y：block 输出，可送入下一层。

原始 Transformer 和现代 LLM block 有什么不同

本教程先讲原始 Transformer 的 block，是为了让概念最清楚。真实大模型经常会替换其中一些部件， 但它们仍然沿用“attention + 残差 + 归一化 + FFN”的大框架。

部件原始 Transformer 常见讲法现代 LLM 常见做法为什么要变
LayerNorm 位置常讲成 attention/FFN 后再 norm，也就是 post-norm。很多 LLM 使用 pre-norm，先 norm 再进 attention/FFN。深层训练更稳定，梯度更容易传播。
位置编码sin/cos positional encoding。RoPE、ALiBi 或 learned position 等。更适合长上下文、相对位置和外推。
FFN 激活ReLU 或 GELU。SwiGLU / GeGLU 等门控 FFN。表达能力更强，训练效果更好。
Attention 结构每个 head 都有独立 Q/K/V。GQA/MQA 会减少 KV head 数。降低 KV cache 显存和推理成本。
学习顺序建议： 先把原始 block 学明白，再看现代变体。变体不是推翻原理，而是在稳定性、显存、长上下文和吞吐上做工程优化。

一步步看 block 在做什么

  • 输入 X：每个 token 已经有 embedding 和位置编码。
  • MultiHeadAttention：每个 token 从其他 token 取回上下文，得到 A。
  • 残差连接：X + A 保留原始信息，同时加入上下文信息。
  • LayerNorm：把每个 token 向量的尺度调稳定，便于深层堆叠。
  • FFN：对每个 token 单独做非线性加工。

LayerNorm 和 FFN 的公式

LayerNorm(z) = gamma * (z - mean(z)) / sqrt(var(z) + eps) + beta FFN(h) = W2 * activation(W1 * h + b1) + b2
z：某一个 token 的向量。
gamma/beta：可学习缩放和平移参数。
activation：非线性函数，如 ReLU、GELU。
FFN：逐 token 执行，不在 token 之间传信息。

手工跟踪一个词：bank 如何被上下文改写

句子 I deposited money at the bank 中，bank 一开始可能同时含有“银行”和“河岸”的可能性。 一个 block 会按下面的方式逐步加工它：

  1. 输入 X：bank 先带着自己的词向量和位置信息进入 block。
  2. Attention：bank 关注 deposited 和 money，取回金融语境信息。
  3. 残差：模型把原始 bank 向量加回来，避免上下文把词本身洗掉。
  4. LayerNorm：把向量数值调到稳定范围，方便很多层继续堆叠。
  5. FFN：逐 token 加工，把“bank + deposited + money”的信号进一步推向“银行”。

教学例子：从词到上下文含义

本章小结

  • Transformer block 不是只有 attention，它还包含残差、LayerNorm 和 FFN。
  • 残差保留原信息，LayerNorm 稳定数值，FFN 增加非线性表达能力。
  • 多个 block 堆叠后，token 表示会从浅层上下文逐步变成更抽象的任务表示。

5. Encoder-Decoder：原始 Transformer 如何做翻译

原始论文的 Transformer 是 encoder-decoder 架构。Encoder 读取完整源句，decoder 一步步生成目标句，并通过 cross-attention 查询源句。

先把翻译想成“先读懂，再写出”

翻译不是直接把每个英文词替换成中文词。模型要先理解完整源句，再按目标语言的顺序一个 token 一个 token 写出来。 这就是 encoder-decoder 的基本分工：encoder 像阅读者，decoder 像写作者。

Encoder 可以看完整源句，因为源句一开始就给定；decoder 不能看未来目标词，因为生成时未来词还不存在。 这就是为什么 decoder 需要 masked self-attention。

先后依赖： Encoder-decoder 架构把前面学过的 block 分成两种角色：encoder 负责读懂输入，decoder 负责按顺序生成输出。 翻译、摘要、改写这类“输入一段文本，输出另一段文本”的任务很适合这种结构。

三种 attention 位置

  • Encoder self-attention：源句内部所有 token 互相看，因为整句已经给定。
  • Decoder masked self-attention：目标句生成时只能看已经生成的 token，不能偷看未来。
  • Cross-attention：decoder 当前状态拿 query 去看 encoder 输出的 key/value，从源句取信息。
masked_score_ij = score_ij + mask_ij CrossAttention(Q_dec, K_enc, V_enc) = softmax(Q_dec K_enc^T / sqrt(d_k)) V_enc
mask_ij：如果 key 位置 j 是未来 token，就设成很大的负数；否则为 0。
Q_dec：decoder 当前已生成前缀产生的 query。
K_enc/V_enc：encoder 对源句产生的 key 和 value。
CrossAttention：让 decoder 当前步从源句中取相关信息。
EncoderSelfAttention: Q/K/V all come from X_src DecoderMaskedSelfAttention: Q/K/V all come from target prefix CrossAttention: Q comes from decoder, K/V come from encoder
X_src：源语言输入的 token 表示。
target prefix：目标语言已经生成的前缀。
Q_dec：decoder 当前想问的问题。
K_enc/V_enc：encoder 保存的源句信息。

逐步翻译：从 I like apples 到 我 喜欢 苹果

  1. Encoder 阶段：I、like、apples 互相做 self-attention，形成“带上下文批注的源句记忆”。
  2. Decoder step 1：目标前缀只有起始符号，decoder 查询源句，重点看 I，生成 我。
  3. Decoder step 2：目标前缀是 我，decoder 只能看这个前缀，同时 cross-attention 看源句里的 like，生成 喜欢。
  4. Decoder step 3：目标前缀是 我 喜欢，decoder 查询源句里的 apples，生成 苹果。
  5. 结束：模型生成结束符号，说明目标句完成。

本章小结

  • Encoder 负责读完整输入，decoder 负责按顺序生成输出。
  • Decoder masked self-attention 防止偷看未来目标 token。
  • Cross-attention 让 decoder 每一步都能查询 encoder 保存的源句信息。
  • GPT 类 decoder-only 模型通常没有单独 encoder，也没有原始 encoder-decoder 那种 cross-attention。

6. 训练目标与损失：模型到底在优化什么

很多语言模型训练的核心目标是：给定上下文，预测下一个 token。模型先输出 logits，再经过 softmax 变成概率分布，最后用 cross entropy 惩罚错误答案。

先把训练看成“做题、打分、改错”

一个学生做题后，老师会给分，并指出哪里错了。模型训练也类似：模型根据前文预测下一个 token， loss 给这个预测打分，优化器根据 loss 调整参数。这里的“题目”不是人工编的选择题，而是从大量文本中自动构造出来的。

本章的依赖流： 前面几章解释了模型如何前向计算出每个位置的表示。本章回答训练时如何给这些表示一个目标： 用当前位置的上下文去预测下一个 token，让正确 token 的概率越来越高。

从训练样本到一个 loss

一段文本不会只产生一个样本，而是会被切成许多“前缀到下一个 token”的监督信号。 例如 我 喜欢 机器 学习 可以形成： 我 -> 喜欢、我 喜欢 -> 机器、我 喜欢 机器 -> 学习。

X = [x_1, x_2, ..., x_n] target_t = x_{t+1} loss = -(1 / (n - 1)) * sum_{t=1..n-1} log P(x_{t+1} | x_1, ..., x_t)
x_t：第 t 个输入 token。
target_t：第 t 个位置要预测的真实答案。
P(x_{t+1} | x_1, ..., x_t)：模型给真实下一个 token 的概率。
1 / (n - 1)：对所有可预测位置取平均，避免长句天然 loss 更大。

不同 Transformer 变体的训练目标不完全一样

本章先用 GPT 式 next-token prediction 讲 loss，因为它最容易和大语言模型推理对应起来。 但 BERT、T5、翻译模型的训练题目并不完全相同。它们共享 Transformer 积木，却用不同方式构造监督信号。

为什么用 cross entropy

模型输出的是词表上的概率分布，真实答案可以看成 one-hot 分布：正确 token 的概率是 1，其他 token 是 0。 Cross entropy 衡量“真实分布”和“模型分布”的距离。因为真实分布只有一个位置为 1，最后会简化成 -log(p_target)。

如果模型给正确答案 90% 概率，loss 约为 -log(0.9) = 0.105； 如果只给 1% 概率，loss 约为 -log(0.01) = 4.605。 它惩罚的是“对正确答案有多没信心”。

梯度直觉：把概率推回正确 token

d loss / d logit_j = p_j - y_j

如果 j 是正确 token，y_j = 1，梯度是 p_j - 1，通常为负，优化器会把它的 logit 往上推。 如果 j 是错误 token，y_j = 0，梯度是 p_j，概率越高，被往下压得越明显。

所以训练不是简单惩罚“答错一次”，而是持续推动模型：让正确 token 的概率更高，让错误 token 的概率更低。

训练时的几个关键工程细节

Teacher Forcing

训练时第 t 个位置使用真实前文作为输入，而不是使用模型自己刚生成的 token。 这样可以并行计算所有位置的 loss，也避免早期模型生成错误后一路滚偏。

Causal Mask

自回归训练必须加 mask。第 t 个位置只能看 x_1...x_t，不能看 x_{t+1}。 否则模型会偷看答案，训练 loss 很低，但推理时不可用。

Batch Loss

实际训练会把多个样本、多个位置的 loss 平均。padding 位置通常要从 loss 中排除， 否则模型会学习“补齐符号”，还会污染评估。

本章小结

  • 语言模型训练常把文本拆成多个“根据前文预测下一个 token”的小问题。
  • Logit 是原始分数，softmax 把 logit 变成概率，cross entropy 把正确 token 的概率变成 loss。
  • Teacher forcing 让训练更稳定，causal mask 防止模型偷看未来。
  • 训练 loss 下降只说明模型更会拟合训练分布，落地还要看验证、评测、安全和成本。

7. BERT、GPT、T5：Transformer 的三条常见演化路线

原始 Transformer 提供了积木。后来的模型根据任务删减或重组这些积木：BERT 保留 encoder，GPT 保留 decoder，自然语言到自然语言转换模型保留 encoder-decoder。

先用三个问题区分它们

初学者常把 BERT、GPT、T5 都混成“大模型”。更好的区分方式不是先问参数量，而是先问信息流： 模型能不能看完整输入？它是不是必须从左到右生成？它输出的是向量分数，还是一段新文本？

判断问题BERTGPTT5

训练时常做什么题？遮住 token 再恢复。预测下一个 token。把输入文本转换成目标文本。
输出更像什么？可分类、可比较的表示。一个接一个的新 token。一段目标文本。

GPT：把任务改写成“继续生成”

GPT 的核心是自回归生成。给定 prompt，模型每次预测一个新 token，然后把新 token 接回上下文继续预测。 分类、抽取、问答、代码生成都可以包装成“请按指定格式生成答案”。

这种统一接口非常灵活，但也带来工程挑战：输出格式可能漂移，事实可能幻觉，长 prompt 会增加 prefill 成本，多轮对话还需要管理历史上下文。

T5：把任务统一成“文本到文本”

T5 保留 encoder-decoder 结构。Encoder 先读完整输入，decoder 再生成输出，并通过 cross-attention 回看输入。 它很适合输入和输出都比较明确的转换任务，比如翻译、摘要、改写和问答。

任务输入文本输出文本
翻译translate English to Chinese: machine learning机器学习
摘要summarize: 一篇很长的文章...文章的简短摘要...
问答question: ... context: ...答案文本
工程经验： 一个完整 AI 应用通常不是“一个大模型解决所有问题”，而是多种 Transformer 变体协作：embedding 召回候选，reranker 提升相关性，LLM 生成答案，规则或校验器保证输出可用。

本章小结

  • BERT 更像“阅读理解器”，适合分类、匹配、抽取、embedding 和 rerank。
  • GPT 更像“续写生成器”，适合对话、代码、工具调用和开放式生成。
  • T5 更像“文本转换器”，适合翻译、摘要、改写和输入输出边界明确的任务。
  • 实际系统常组合使用多种模型，而不是所有环节都交给同一个最大模型。

8. LLM 推理工程：KV cache、上下文窗口和采样

当 Transformer 变成大语言模型，工程问题会变得非常具体：显存够不够、首 token 为什么慢、长上下文为什么贵、采样参数如何影响输出。

先把一次 LLM 请求拆成几段

用户感觉到的“慢”不是一个单点问题。提交 prompt 后，系统要先把文本转成 token，然后处理完整 prompt， 再一个 token 一个 token 地生成回答。首 token 出来慢，通常和 prefill、排队、prompt 长度有关；开始输出后速度慢，通常和 decode 吞吐有关。

从模型结构走向服务链路： LLM 推理通常分成请求接入、tokenize、prefill、decode、采样、detokenize 和流式返回。 首 token 延迟主要受 prefill 影响，后续输出速度主要受 decode 吞吐影响。
阶段做什么主要瓶颈优化方向
Tokenize把文本转成 token id。长 prompt、复杂模板、多轮历史拼接。缓存系统 prompt，减少重复拼接，控制历史长度。
Prefill并行处理完整 prompt，生成第一步所需 KV cache。上下文越长，注意力计算和显存压力越大。prompt 压缩、chunk prefill、批处理、FlashAttention。
Decode每次生成一个 token，并追加 KV cache。逐步依赖强，GPU 容易吃不满。continuous batching、PagedAttention、speculative decoding。
Sampling根据 logits 选择下一个 token。参数不合适导致重复、跑题或格式不稳。temperature、top-p、重复惩罚、结构化约束。

prefill 与 decode

用户输入 prompt 后，模型先并行处理整段 prompt，这叫 prefill。之后每次只生成一个新 token，这叫 decode。 decode 阶段如果每一步都重新计算所有历史 token 的 key/value，就会浪费大量计算。

KV cache 的做法是缓存历史 token 的 key 和 value。生成新 token 时，只计算新 token 的 query、key、value，然后让新 query 去看缓存里的历史 key/value。

without_cache_cost ≈ L * sum_{t=1..n} t^2 with_cache_cost ≈ L * sum_{t=1..n} t
L：Transformer 层数。
n：已经生成的 token 数。
t^2：重算第 t 步完整 attention 矩阵的近似成本。
t：只用新 query 看历史 key/value 的近似成本。
kv_cache_size ≈ batch_size * layers * seq_len * 2 * kv_heads * head_dim * bytes_per_value
batch_size：同时服务的请求数。
layers：Transformer 层数。
2：每层要缓存 key 和 value 两份张量。
seq_len：prompt token + 已生成 token 的总长度。
kv_heads：KV head 数，使用 MQA/GQA 时会小于 query head 数。
bytes_per_value：FP16/BF16 通常是 2 字节，INT8 cache 更小但有精度取舍。

上下文窗口

上下文窗口是模型一次能看到的 token 数上限。它不是长期记忆，只是当前请求里的可见范围。

temperature

temperature 越低，概率分布越尖，输出更保守；越高，低概率 token 更容易被采样，输出更多样但更不稳定。

top-k / top-p

它们不是训练算法，而是推理采样策略：先截断候选集合，再从剩余 token 中采样。

线上问题表现工程处理
请求过长首 token 慢，挤占 KV cache。限制上下文长度，检索裁剪，摘要压缩，长文任务异步化。
输出不可控JSON 解析失败、格式漂移、答案过长。schema 约束、停止词、max tokens、低温采样、失败重试。
GPU 利用率低单请求 decode 时 GPU 空转明显。continuous batching，多租户队列，合并短请求。
显存不足长上下文或高并发触发 OOM。量化、GQA/MQA、PagedAttention、降低并发或上下文上限。

一个线上延迟例子

假设用户给了 4000 个 prompt token，模型要生成 300 个 token。首 token 之前，模型必须先处理那 4000 个 token，这就是 prefill。 后面 300 个 token 不能一次全部生成，因为第 101 个输出依赖前 100 个输出，所以 decode 是逐步进行的。

总耗时 ≈ tokenize + prefill(prompt) + decode(300 tokens) + 网络/渲染

所以优化方向要分清楚：如果首 token 慢，优先看 prompt 长度、排队和 prefill；如果流式输出慢，优先看 decode 吞吐、batching 和 KV cache。

本章小结

  • Prefill 决定首 token 前要处理多少上下文，decode 决定后续 token 的生成速度。
  • KV cache 能减少重复计算，但会随层数、上下文长度和并发占用显存。
  • 上下文窗口不是长期记忆，temperature/top-k/top-p 只改变采样方式，不增加事实知识。
  • 线上优化要同时看质量、延迟、吞吐、显存和成本，不能只盯模型大小。

9. 实践意义与常见误区

理解 Transformer 的目标不是背公式，而是在工程决策里知道哪些事情可靠，哪些只是表面相似。工程上真正有价值的是：知道什么时候该用 embedding，什么时候该用生成模型，什么时候问题根本不在模型。

先用一个真实工程问题校准直觉

假设你要做一个“企业知识库问答”系统，用户问：“上个月线上故障的根因是什么？” 如果直接把问题丢给大模型，模型可能会给出流畅但不可靠的答案，因为它不一定看过你的内部故障文档。

更稳的系统通常是：先用 embedding 检索相关文档，再用 reranker 排序，把最相关片段和引用来源放进 prompt， 最后让模型组织答案。模型负责语言组织，事实来源来自检索到的材料。

本章定位： 前 8 章解释了 Transformer 如何把 token 变成上下文向量、如何训练、如何推理。 本章把这些知识转回工程判断：检索、问答、分类、摘要、代码生成和长上下文应用分别应该关注什么。

落地判断清单

  • 语义检索：如果你要“找相似内容”，通常先考虑 embedding 检索。它把文本压成向量，用距离或相似度找候选，比让大模型逐条阅读全库更便宜。
  • 排序增强：如果候选少但质量要高，可用 reranker 或 cross-encoder 重新打分。
  • 问答系统：如果答案依赖私有知识、实时数据或长文档，单靠 prompt 不可靠。通常需要 RAG、工具调用、数据库查询或显式引用来源。
  • 分类任务：如果类别稳定、样本充足、延迟敏感，小模型或专门分类器可能比大模型更合适。
  • 结构化输出：如果业务需要固定 JSON、字段校验或强约束流程，要结合 schema、解析器、重试和后置校验。
  • 微调：当输出格式、领域语言或稳定行为长期重复出现，才考虑 fine-tuning。
  • 长上下文：长窗口能放更多内容，但注意力成本、位置外推和噪声干扰都要评估。

关于模型理解的误区

  • 误区 1：attention 权重不等于完整解释。它只是一次前向计算里的权重。
  • 误区 2：模型不是直接读中文或英文字符，它读的是 tokenizer 产生的 token id。
  • 误区 3：embedding 不是词典释义，它是训练中学到的连续向量，表达统计关系和任务相关特征。
  • 误区 4：更大模型通常更强，但延迟、费用、隐私、部署方式和稳定性同样重要。

关于推理使用的误区

  • 误区 5：temperature 不能让模型更懂，只是在已有概率分布上改变采样行为。
  • 误区 6：上下文窗口不是数据库，也不是长期记忆。请求结束后它不会自动记住。
  • 误区 7：RAG 不等于“把文档塞进 prompt”，它包含切分、召回、排序、引用、冲突处理和答案校验。
  • 误区 8：模型输出看起来像 JSON，不代表一定可解析。生产系统要做解析、校验、错误恢复和审计。

  • Embedding、reranker、LLM、规则和人工审核不是互斥关系，常常需要组合。

  • 生产系统不要只追求“生成得像”，还要能追溯、可解析、可审计、可恢复。

10. 总复盘：把链路串起来

Transformer 的完整链路可以压缩成一句话：把文本拆成 token，把 token 变成含位置的向量，让每个位置反复从上下文取信息，最后输出任务需要的概率或向量。

最后一章不引入新概念，只做“串联”

如果前面每章像一个模块，这一章就是把模块连成系统图。你需要能从一个业务需求反推：文本如何进入模型、模型如何计算、 训练目标是什么、推理成本在哪里、系统可靠性靠什么保证。

text -> tokens -> token ids -> embeddings + positions -> Transformer blocks -> logits / vectors -> task output
tokens：文本被 tokenizer 切成模型能处理的片段。
embeddings：token id 查表得到的连续向量。
positions：告诉模型顺序信息，避免只看到一袋 token。
blocks：多层 attention、残差、归一化和前馈网络。
logits：生成任务中 softmax 前的候选 token 分数。
vectors：检索、分类或表征任务中可直接使用的语义表示。

十章主线回顾

  • 第 0 章：Transformer 的核心动机是让序列中任意位置直接建立关系。
  • 第 1 章：文本必须先变成 token id，再查表得到 embedding，并加入位置信息。
  • 第 2 章：attention 的本质是打分、softmax、加权求和。
  • 第 3 章：multi-head attention 让模型并行学习不同关系。
  • 第 4 章：Transformer block 用残差、LayerNorm 和 FFN 把 attention 变成可堆叠网络。
  • 第 5 章：encoder-decoder 适合翻译等序列到序列任务。
  • 第 6 章：训练目标通常是让正确 token 的概率变高。
  • 第 7-9 章：架构选择、推理优化和工程落地都要围绕信息流、成本和可靠性做判断。

一眼判断：你真正学会了什么

  • 看到 QK^T 时，知道它是在计算每个 query 对每个 key 的匹配分数。
  • 看到 softmax 时，知道它把一组分数变成总和为 1 的权重或概率。
  • 看到 mask 时，知道它是在控制可见范围，尤其是 decoder 生成时不能看未来。
  • 看到 KV cache 时，知道它缓存的是历史 key/value，不是模型的长期记忆。
  • 看到 temperature 时，知道它影响采样随机性，不提升事实准确性。

复盘问题：概念层

  • 为什么 token id 不能直接表示语义？因为 id 只是词表行号，模型需要 embedding 把它映射成连续向量。
  • 为什么 attention 需要位置编码？因为没有位置信息时，相同 token 的不同顺序很难区分。
  • 为什么要除以 sqrt(d_k)？为了避免点积分数过大，使 softmax 过早变得极端。
  • 为什么 decoder 要 mask 未来 token？因为预测当前位置时不能偷看后面的答案。

复盘问题：工程层

  • 为什么首 token 慢？模型要先处理完整 prompt，并构建 KV cache。
  • 为什么 decode 阶段吞吐难做高？生成是逐 token 依赖的，下一步依赖上一步输出。
  • 为什么长上下文不等于更可靠？它更贵，也可能引入无关信息，干扰真正重要的证据。
  • 为什么结构化输出必须校验？模型生成的是文本，不保证每次满足 JSON、字段类型和业务规则。

术语速查

术语一句话含义容易混淆点
token模型处理文本的基本单位，可能是词、子词、标点或字节片段。不是自然语言里的“一个词”。
token idtoken 在词表中的整数编号。模型实际接收的是 id，不是字符串。
embedding把 token id 映射成连续向量的查找表或向量结果。不是人工写好的词义表。
position encoding给 token 向量加入顺序信息。没有它，attention 本身不天然知道顺序。
query当前 token 发出的“我想找什么信息”。来自输入向量乘以可学习矩阵。
key被其他 token 匹配的“索引特征”。和 query 点积后得到 attention 分数。
value被 attention 权重加权汇总的内容向量。真正被拿走的是 value，不是 key。
mask禁止模型看到某些位置。常用于 decoder 防止偷看未来 token。
logitssoftmax 之前的原始分数。不是概率，可以为负，也不要求总和为 1。
KV cache推理时缓存历史 key/value，减少重复计算。不是数据库，也不是长期记忆。
RAG先检索外部资料，再把相关内容交给模型生成答案。质量取决于切分、召回、排序和引用链路。
