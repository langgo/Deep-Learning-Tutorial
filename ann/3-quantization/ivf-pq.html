IVF-PQ · 倒排索引 + 乘积量化

先用粗聚类"分区"，只对少数分区做 PQ 精排 —— 十亿向量级检索的工业事实标准。

前置阅读： 前置：PQ（必读） · K-Means · Voronoi 概念 建议顺序：SQ → PQ → IVF-PQ (当前) → OPQ
关键术语速查（点击展开）
倒排索引 IVF (Inverted File)
先对全库做一次粗聚类把向量分到 nlist 个桶，查询时只看跟自己最近的几个桶。是从"文本检索的倒排链表"演化来的思路。
Voronoi 单元
每个粗中心 μ 的势力范围：平面上任意点属于最近的那个 μ。想象一张地图分成 nlist 个区域，每个区域有一个"首都" μ。
残差 residual
r = x − μb(x)，即向量减去它所属桶的质心。物理含义 = 该向量相对本桶中心的偏移量。同桶内残差分布集中、方差小，PQ 训练误差更低。
nlist
number of inverted lists，桶数。经验：nlist ≈ √N 到 8√N。
nprobe
number of probes，查询时探测几个桶。是召回率 vs 速度的核心旋钮：nprobe 越大越准越慢。
posting list
每个桶对应的向量 ID 列表（存的是编码后的 PQ 码字，不是原向量）。
IVFADC
IVF + Asymmetric Distance Computation，即 IVF-PQ 的完整名字。
新手引导 · 建议按顺序体验：
  1. 先看主图的 Voronoi 分区着色：不同色块 = 不同粗中心 μ 的势力范围。
  2. 拉动 nprobe 从 1 到 8，观察被"高亮"（不透明）的桶数量变化，以及 召回率和扫描比例指标变化。
  3. 拉动 nlist 从 4 到 48，观察 Voronoi 单元变多变小，桶大小直方图更细。
  4. 点击画布任意位置换查询点，或拉动 N（数据点数）看不同规模下召回稳定性。

一、直观理解

类比：图书馆分区找书

假设你在一个 100 万本书的图书馆找一本相似题材的书：

  • 暴力搜：把每本书翻一遍 → 太慢
  • IVF (Inverted File 倒排文件)：先根据"题材"分成 1000 个书架 (Voronoi 单元)，你只去最相关的 8 个书架找 (nprobe=8)。
  • 每个书架里书还是很多 → 每本书用 PQ 编码压缩到 8 字节，然后用 LUT 快速比距离。

IVF 负责剪枝，PQ 负责精细压缩+快速距离，两者组合覆盖"大范围粗过滤 + 局部精排"两个层次。

关于 Voronoi 单元：= 每个粗中心 μ 的势力范围，平面上任意点属于离它最近的那个中心。想象一张地图分成 1000 个区域，每个区域有一个"首都" μ，每本书自动归属离它最近的首都。

为什么 IVF 和 PQ 是绝配？

  • 纯 PQ：即使查询快，仍要扫描全部 N 条编码 → O(N) 加法。N=10⁹ 时 10 亿次加法太慢。
  • 纯 IVF：内存里塞不下 10⁹ 个 float32 向量。
  • IVF-PQ：内存只存 N × M 字节 PQ 码 (10 亿×8B = 8GB)，查询只扫 nprobe/nlist 部分向量 (比如 1/128) → 8000 万条 * 8 次加法 ≈ 微秒-毫秒级。

2.1 两级结构

粗量化 (IVF)：对训练集做 K-Means 得到 nlist 个粗中心 {μ1, ..., μnlist}。每个中心 μi 对应一个"桶" (posting list)。
残差 PQ：对每个向量 x，先找最近粗中心 μi，计算残差 r = x − μi，再对残差做 PQ 编码。
为什么用残差而不是原向量？因为同一桶内向量的残差分布更集中、方差更小，量化误差显著降低。

直觉：残差为什么能降误差？

把"整本书的绝对坐标"换成"这本书在书架里的相对偏移量"。

  • 原向量 x：分布覆盖整个空间，方差大 → PQ 一次要覆盖所有区域，K=256 中心分散到很稀。
  • 残差 r = x − μ：以桶中心为原点，同一书架里的书偏移量普遍很小、集中在原点附近，方差小几倍。

同样是 K=256 的 PQ 码本，训练残差比训练原向量，每个中心能覆盖更精细的区域，误差往往降到 1/2~1/3。

2.2 索引构建流程

def build_ivfpq(X, nlist, M, K_pq):
    # 1) 粗聚类 K-Means (常用: nlist = √N)
    coarse_centers = kmeans(X, nlist)
    # 2) 分桶 + 残差
    residuals = []
    postings = defaultdict(list)      # bucket_id -> [(xid, code)]
    for i, x in enumerate(X):
        b = argmin_j ||x - coarse_centers[j]||
        r = x - coarse_centers[b]
        residuals.append(r)
        # 记 bucket, 稍后编码
    # 3) 用所有残差训练 PQ (共享码本)
    pq_codebooks = train_pq(np.array(residuals), M, K_pq)
    # 4) 编码残差
    for i, x in enumerate(X):
        b = argmin_j ||x - coarse_centers[j]||
        r = x - coarse_centers[b]
        code = pq_encode(r, pq_codebooks)
        postings[b].append((i, code))
    return coarse_centers, pq_codebooks, postings

2.3 查询流程 (IVFADC = IVF + Asymmetric Distance)

def search(y, nprobe, topk):
    # 1) 找 y 最近的 nprobe 个粗中心
    coarse_dists = [(j, ||y - coarse_centers[j]||^2) for j in range(nlist)]
    coarse_dists.sort(key=lambda t: t[1])
    probe_buckets = [j for j, _ in coarse_dists[:nprobe]]

    # 2) 每个 probe 桶单独算 LUT
    candidates = []
    for j in probe_buckets:
        r_query = y - coarse_centers[j]         # 桶内比较用残差
        LUT = precompute_lut(r_query, pq_codebooks)   # (M, K)
        for xid, code in postings[j]:
            d_approx = sum(LUT[m, code[m]] for m in range(M))
            candidates.append((xid, d_approx))
    # 3) 取 top-k
    return heapq.nsmallest(topk, candidates, key=lambda t: t[1])

2.4 参数与内存分析

先看统一基线 D=128, N=106：

  • 暴力 float32：128 × 4 × 106 = 512 MB，扫描 106 条。
  • IVF-PQ (nlist=1024, nprobe=16, M=8, K=256)：粗中心 1024×128×4B = 512KB + PQ 码 106×8B = 8 MB；每次扫描 ≈ 106 × 16 / 1024 ≈ 16000 条。

再看亿级扩展 D=128, N=109：

  • nlist = 4096 (≈ √N 的一半到全值)：粗中心存储 4096 × 128 × 4B = 2 MB
  • nprobe = 32：每次查询遍历 N × nprobe/nlist ≈ 8 × 10⁶ 条编码
  • PQ M=16, K=256：每条 16 字节，总计 16 GB
  • 加速比相比暴力 float32 (128×4×N = 512 GB, 全扫)：内存 32×、扫描 128×

2.5 关键公式

近似距离 (residual-based, IVFADC): d̂(y, x)² = ‖y − (μb(x) + q(x − μb(x)))‖²

展开可得 (y' = y − μb, r = x − μb, q(r) 为 PQ 重构):

d̂² = ‖y' − q(r)‖² = Σm ‖y'm − cm,qm(r)‖²

关键：y 对每个 probe 桶重新算残差和 LUT。所以 nprobe 越大，LUT 计算越多，但候选也越多、召回越高。

四、参数选择经验

参数建议调整方向
nlist√N ~ 8√N (10⁶ 数据 → 1024~4096)大: 精 (桶变小) 但训练慢；小: 快但召回差
nprobe1% ~ 10% 的 nlist大: 高召回但慢；线性权衡
M4 / 8 / 16大: 精但字节多
K (PQ)256 (正好 1 字节)不常改

经验：召回率 90% 时通常 nprobe/nlist ≈ 1%~5%；追求 99% 时可能要 10%。

五、优缺点 & 适用场景

优点

  • 亿级向量的最强量化方案之一 (低内存 + 快)
  • 参数可调，召回-延迟折衷灵活
  • 支持 GPU 批量加速 (Faiss GPU)
  • 可叠加 OPQ (IVF-OPQ-PQ), HNSW (作为 quantizer)

缺点

  • 需训练两次聚类 (IVF + PQ)
  • 桶分布不均时长尾桶变慢
  • 不支持增量更新友好 (新数据只能追加)
  • 召回上限低于图索引 (HNSW)
工业实践：Faiss IndexIVFPQ, Milvus IVF_PQ, ElasticSearch ivfpq。搭配 GPU 时 QPS 可达 10 万+/秒 (10 亿库)。

常见误区

  • nlist 太大 → 每个桶变小、召回崩塌：每桶只有几十个点时，nprobe 需要开很大（20%+）才能维持召回，反而失去 IVF 剪枝的意义。经验：每个桶至少 100~1000 个点。
  • nprobe 太小召回低，太大速度慢：这是速度-召回率的核心旋钮。生产上先固定召回目标（如 95%），二分找最小 nprobe。
  • 桶分布不均衡（幂律分布）：K-Means 对不均衡数据敏感，可能出现少数超大桶。桶大小直方图必看——如果最大桶 / 最小桶 > 100，需要考虑重训练或加正则化。
  • 训练数据必须有代表性：训练集分布偏离在线数据时，粗中心 μ 落在错误位置，召回直接掉。经验：训练集至少 30 × nlist 条，且从线上真实数据抽样。
下一步学什么？
  • IVF 粗中心太多、粗查询本身也慢 → HNSW 或 IVF-HNSW（用 HNSW 加速 IVF 的最近粗中心查找）。
  • PQ 部分误差偏大 → 叠加 OPQ 变成 IVF-OPQ-PQ，Faiss 中即 OPQMatrix + IndexIVFPQ。
  • 更前沿：ScaNN（各向异性量化）、DiskANN（大内存驻留 + SSD 精排）。
