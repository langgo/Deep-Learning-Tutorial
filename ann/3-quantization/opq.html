OPQ · 优化乘积量化 (Optimized Product Quantization)

在 PQ 之前先"旋转"数据，把子空间调成互相独立且能量均衡，把量化误差进一步压下去。

前置阅读： 前置：PQ（必读） · 线性代数基础（正交矩阵、SVD） 建议顺序：SQ → PQ → IVF-PQ → OPQ (当前，最难)
关键术语速查（点击展开）
正交矩阵 (Orthogonal Matrix)
满足 RTR = I 的方阵。几何意义：不改变距离和角度的纯旋转（或镜像）——你把点云拿起来转一下，两两距离完全不变。
Procrustes 问题
给两朵点云 X 和 X̂，找一个正交矩阵 R 使得 R·X 尽量对齐 X̂，即 min ‖RX − X̂‖2。有闭式解（用 SVD 求）。
SVD（奇异值分解 Singular Value Decomposition）
任意矩阵可分解为 A = U Σ VT，U 和 V 是正交矩阵，Σ 是对角矩阵（奇异值）。是 Procrustes 的求解工具。
PCA（主成分分析 Principal Component Analysis）
找数据方差最大的方向作为第一主轴。用协方差矩阵的特征向量作为新坐标系。
白化 (Whitening)
先 PCA 转到主轴，再各维除以对应标准差，使各维方差都等于 1。
参数化 OPQ (P-OPQ)
假设数据服从多元正态，一次 PCA + 方差重排就能算出最优 R，无需迭代。快但表达力受限。
非参数化 OPQ (NP-OPQ)
不假设分布，"固定 R 训 PQ ↔ 固定 PQ 求 R"交替迭代 T 轮。慢但精度更高。
新手引导 · 建议按顺序体验：
  1. 先拉动 数据倾斜角度 到 30~45°，让数据云斜着长（更容易看清 OPQ 的好处）。
  2. 观察左右两图：左 = 原始 PQ（格子横平竖直），右 = OPQ 旋转后（格子沿数据主轴对齐）。看"平均量化误差"数字对比。
  3. 拉动 OPQ 迭代次数 T 从 0 到 20，看下方误差曲线是否单调下降/收敛。
  4. 拉动 K（每段簇数）观察 K 越大格子越密，OPQ 相对 PQ 的收益变化。

一、直观理解

类比：把长方形西瓜放进正方形冰格

PQ 分段就像把西瓜切块放冰格：如果西瓜是沿着某个斜方向的长条，直接横切竖切会切出很多"半空的块"（能量集中在少数格子）； 如果你能先把西瓜转正（找到主轴对齐坐标轴），再切就整齐得多。

OPQ 就是学习一个正交矩阵 R，先做 x → Rx，让每段子向量的能量更均衡、彼此更独立，然后再做标准 PQ。

为什么 PQ 会失效？

PQ 假设"子空间之间独立"、"每段能量差不多"。如果数据在 128 维空间沿某几个方向的方差远大于其它方向 (例如 PCA 后一半维度几乎无信息)， PQ 会：

  • 某些段的信息量太大，K=256 中心不够用 → 误差大
  • 某些段几乎不携带信息 → K 个中心浪费

OPQ 的目标 = 学一个旋转 R，让 各段能量均衡 + 段间相关性低，从而每段的 K-Means 都发挥满效果。

二、算法原理

本页统一基线：下文分析以 D=128, N=100 万, M=8, K=256 为例。R 矩阵额外占 D²×4B = 64 KB 一次性存储。

核心直觉：为什么要"先旋转再量化"？

PQ 把 D 维向量切成 M 段横平竖直地量化。但如果数据是一朵斜着躺的西瓜形状，横切竖切会切出很多"半空的块"——能量集中在少数格子，其它格子浪费。

我们想找一个不改变距离的"纯旋转"（不能拉伸、不能镜像），使得旋转后各段方差更均衡。这种旋转在数学里叫 正交矩阵（满足 RTR = I）。

形象比喻：你有一颗西瓜形数据点云横躺着，直接切 M 段会切得很不均匀；先把它转正让长轴对齐坐标轴，再切段就均匀多了。转的过程不改变任何两点距离——这一点是数学上的黄金：距离不变意味着"检索问题的答案"完全一样，只是更好切段。

2.1 目标函数

OPQ 联合优化 正交矩阵 R 和 码本 {Cm} 与 编码 {q(x)}：

minR,C,q Σx∈X ‖ R·x − [c1,q₁(x); c2,q₂(x); ...; cM,qM(x)] ‖²    s.t. RᵀR = I

2.2 交替优化 (Non-parametric OPQ)

Procrustes 问题直觉

想象两朵点云：X = 原始数据（斜着躺的西瓜），X̂ = PQ 量化重构的数据（横平竖直格子上的点）。我们想找一个旋转 R，让 R·X 尽量重合到 X̂ 上。

这在数学里叫 Procrustes 问题（普罗克鲁斯忒斯问题），来自希腊神话——一个把旅客拉伸压缩到床长的强盗；但正交版本不允许拉伸，只准旋转。

闭式解：计算 M = X · X̂T，做 SVD 得 M = U Σ VT，则最优 R = V UT（或写作 U VT，取决于左右乘约定）。一次 SVD 就完事，不需要梯度下降。

初始化：R = I 或 PCA 主成分排列 (平衡各段能量)。
循环 T 次：
  1. 固定 R，在 Rx 上做标准 PQ：每段独立 K-Means → 得到 {Cm}、编码 q(x)。
  2. 固定 C, q，用 Procrustes 求最优 R：
    设 Y = R·X (旋转后), Ŷ = 重构 = 拼接量化中心。
    求 R = arg min ‖RX − Ŷ‖²，闭式解 = SVD 分解 X·Ŷᵀ = UΣVᵀ，取 R = VUᵀ。

2.3 编码 / 查询

训练完后，编码时 x → R·x → PQ 编码，查询时 y → R·y → PQ LUT 查询。
运行时开销：多一次 D×D 矩阵乘 = O(D²)。对 100 万条向量分摊到查询时可忽略。

2.4 伪代码

def train_opq(X, M, K, T):
    D = X.shape[1]
    R = np.eye(D)                     # 或 PCA 平衡初始化
    for t in range(T):
        Y = X @ R.T                   # 旋转后的数据
        # 步骤 1: 在 Y 上做 PQ
        codebooks = []
        assignments = np.zeros((X.shape[0], M), dtype=int)
        for m in range(M):
            Ym = Y[:, m*d:(m+1)*d]
            Cm = kmeans(Ym, K)
            assignments[:, m] = argmin(Ym, Cm)
            codebooks.append(Cm)
        # 步骤 2: 用 Procrustes 更新 R
        Y_hat = reconstruct(assignments, codebooks)  # (N, D)
        U, _, Vt = svd(X.T @ Y_hat)
        R = (U @ Vt).T                # (D, D) 正交
    return R, codebooks

四、OPQ 变体

Non-Parametric OPQ (NP-OPQ)

上述交替优化，不假设 R 与 C 的具体形式。表达力强，训练成本较高。

Parametric OPQ (P-OPQ)

假设数据服从多元高斯，直接用 PCA 后按方差平衡分组，闭式解一次得 R，无需迭代。快但表达力受限。

五、优缺点 & 适用场景

优点

  • 召回率通常比 PQ 高 5-15%，同码率下误差更低
  • 不改变查询接口，只多一次矩阵乘
  • 可无缝叠加到 IVF-OPQ、HNSW-OPQ

缺点

  • 训练慢 (T 次 SVD)，D 大时代价高
  • 额外 D×D 矩阵存储
  • 对已经"白化"或维度独立的数据提升有限
适用场景：PQ 效果不理想 (数据强相关、能量集中在少数方向)、追求最高召回率的检索系统。Faiss IndexPreTransform + PQ、IndexIVFPQ + OPQMatrix。

常见误区

  • 训练很慢：每轮 SVD 的复杂度是 O(D3)，D=768（BERT embedding）时每轮几秒到几十秒；再乘 T=25 迭代，总时间以分钟计。生产上一般先用 P-OPQ 快速初始化，再跑少量 NP-OPQ 迭代。
  • 不能对新分布数据重新学 R：R 是在训练集上学的旋转，如果查询数据分布 ≠ 训练分布并重新学 R，则数据侧和查询侧使用不同 R → 距离完全错误。R 必须训练一次、终身固定。
  • 加了 OPQ 一定优于纯 PQ 吗？不一定。如果数据本来就已经白化 / 各维方差近似均衡（例如做过 PCA 白化或 L2 归一），OPQ 收益很小甚至可能因为额外矩阵乘变慢。判断标准：先看原始数据的各维方差，如果最大方差/最小方差 > 5 才值得上 OPQ。
  • P-OPQ vs NP-OPQ 选错：P-OPQ 只在数据近似多元高斯时有理论保证。真实嵌入常有多峰或长尾，此时必须 NP-OPQ。
下一步学什么？
  • OPQ + IVF-PQ 的组合 → IVF-OPQ-PQ（Faiss OPQMatrix + IndexIVFPQ），亿级检索的性能天花板之一。
  • 更强的一族：ScaNN（各向异性量化，Google 2020），对内积检索特殊优化，同码率下召回再高 3~5%。
  • 2023+ 前沿：RaBitQ（1-bit 量化 + 理论误差界），冲击 128 倍压缩率而保持高召回。
