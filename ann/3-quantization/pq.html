PQ · 乘积量化 (Product Quantization)

把一个长向量拆成若干短子向量，每段独立用小规模码本表示 —— 用极少的字节撑起海量向量的近似最近邻检索。

前置阅读： 前置：K-Means 聚类基础 · SQ（本类别入门） 建议顺序：SQ → PQ (当前) → IVF-PQ → OPQ
关键术语速查（点击展开）
K-Means
把 N 个点分成 k 组，每组用一个"组中心"代表。反复迭代：① 每个点归到最近中心 → ② 每个中心移到自己组的均值 → ③ 直到不再变化。
码本 codebook
K-Means 学到的 k 个中心的集合。PQ 里每段独立学一本码本，共 M 本。
码字 codeword / code
每个数据点在码本里对应的索引编号（0 ~ K−1）。PQ 编码 = M 个索引。
LUT（查找表 Look-Up Table）
查询到来时预计算的 M×K 表格 LUT[m][k]，之后每条数据距离 = M 次查表 + 加法。
子向量 subvector
把 D 维向量切成 M 段，每段是 d = D/M 维的子向量。
ADC（Asymmetric Distance Computation, 非对称距离计算）
查询侧保持原始浮点向量（不量化），数据侧用码字查表。适合"查询少、数据多"的场景。
SDC（Symmetric Distance Computation, 对称距离计算）
查询也量化，两边都查表。速度更快但误差更大。工业实践里 ADC 是默认选择。
新手引导 · 建议按顺序体验：
  1. 拉动 M（段数） 从 1 到 4，观察子空间数量的变化（M=1 相当于对整个向量做 K-Means，M=2 会看到 X 段和 Y 段分别独立聚类）。
  2. 拉动 K（每段簇数）从 4 到 16，观察格子密度和数据点被吸附到最近格子中心的过程。
  3. 点击 【随机新查询点】 或直接在画布上点击选一个查询位置。
  4. 看下方 LUT 表：每行是一段的查表值。再看"近似距离 vs 真实距离"，验证误差来源。

一、直观理解

类比：把长电话号码分成几段

假设有一个 12 位长号码 138 5827 3941：

  • 如果给整个号码建"字典"，需要 1012 条记录 —— 显然不现实。
  • 如果分成 3 段：138、5827、3941，每段各建一本"常用号码表"（比如各 256 条）， 然后每段只用 1 字节 (log₂256=8 bit) 记录"我是第几号"就好。
  • 整个号码只需 3 字节 存储，就近似还原原始号码。

PQ 就是把这种思路搬到高维向量上：把 128 维向量切成 M=8 段，每段 16 维，每段独立 K-Means 得到 256 个"典型子向量"， 用 M × log₂K = 8 字节 就能压缩表达一个 128 维 float32（原本要 128×4=512 字节，压缩 64 倍）。

为什么"分段量化"比"整体量化"好？

假设我们直接对 128 维向量做 K-Means 得到 K 个中心，要达到与分 8 段各 256 中心相同的表达能力，需要 K = 256⁸ ≈ 1.8 × 10¹⁹ 个中心 —— 完全无法枚举。

PQ 的核心洞察：不同子空间基本独立（比如 128 维图像特征的前 16 维和后 16 维语义不相关）， 所以用"笛卡尔积码本"（Cartesian product codebook）能以 M × K 个中心表达 K^M 种组合。

二、算法原理

先补：K-Means 一分钟速讲

K-Means 做的事：给你 N 个点，找 k 个中心，使得每个点到最近中心的距离和最小。

  1. 随机初始化 k 个中心。
  2. 分配：每个点归到离它最近的中心。
  3. 更新：每个中心移动到自己组的所有点的均值位置。
  4. 回到步骤 2，反复迭代到中心不再变化（一般 10~30 轮）。

在 PQ 里，K-Means 用来为每段子向量学一个 K 个中心的码本；聚类完成后，每个数据点用"距离最近的中心编号"表示。

本页统一基线：下文分析以 D=128, N=100 万, M=8, K=256 为例，得到 8 字节/向量 → 8 MB 总内存（相比原始 512 MB，压缩 64×）。

2.1 记号定义

  • x ∈ ℝD：原始向量，维度 D（例如 128）
  • M：子空间数量（一般取 4/8/16）
  • d = D / M：每段子向量维度
  • K：每段码本大小（通常 256，正好对应 1 字节）
  • Cm = {cm,1, ..., cm,K}：第 m 段的码本

2.2 编码 (Encoding)

把 x 切成 M 段子向量：x = [u₁; u₂; ...; uM]，每段 um ∈ ℝd。

硬约束：D 必须整除 M

因为每段要平均分到 d = D/M 维。例如 D=128 时 M 只能取 {1, 2, 4, 8, 16, 32, 64, 128}；不能取 20 或 12。工业实践里最常用 M=8（d=16）或 M=16（d=8）。

对每段独立找最近的码本中心：

qm(x) = arg mink ∈ [1,K] ‖um − cm,k‖²

编码结果：code(x) = (q₁, q₂, ..., qM)，占 M · log₂K 比特。

2.3 非对称距离查询 ADC (Asymmetric Distance Computation)

查询向量 y 也切成 M 段：y = [v₁; v₂; ...; vM]。

预计算查找表 LUT (每次查询只算一次)：

LUT[m][k] = ‖vm − cm,k‖², m ∈ [1,M], k ∈ [1,K]

对数据库中每个向量 x，其近似距离由 M 次 LUT 查表求和：

d̂(y, x)² = Σm=1..M LUT[m][qm(x)]

好处：不再需要还原原向量、不再做浮点乘加 —— 100 万条向量的距离计算变成 100 万次"查 8 次表 + 加法"。

直觉：为什么叫"非对称"？为什么这样设计？

非对称指查询侧 y 保持原始浮点（精确无损），数据侧 x 被量化（有误差）—— 两边精度不对称。

为什么这样设计？典型场景是一次查询要跟百万条数据算距离：

  • 如果只把数据端量化 → 只需预计算一次 LUT（M×K 个距离），然后每条数据 = M 次查表 + M 次加法。
  • 如果把查询也量化（SDC）→ 距离误差更大，但少了一次 LUT 计算。查询 QPS 极高时才用。

工业实践中 ADC 是默认，因为量化后的数据是主要成本源（几十 GB 到几 TB），查询侧误差不值得省。

2.4 训练流程 (伪代码)

# 输入: 训练集 X ∈ ℝ^{N×D}, 段数 M, 每段簇数 K
def train_pq(X, M, K):
    D = X.shape[1]
    d = D // M
    codebooks = []
    for m in range(M):
        # 切出第 m 段
        Xm = X[:, m*d:(m+1)*d]
        # 对该段做 K-Means
        Cm = kmeans(Xm, K)             # (K, d)
        codebooks.append(Cm)
    return codebooks

def encode(x, codebooks):
    codes = []
    for m, Cm in enumerate(codebooks):
        um = x[m*d:(m+1)*d]
        k_star = argmin_k ||um - Cm[k]||^2
        codes.append(k_star)
    return codes                       # M 个整数

def search(y, database_codes, codebooks):
    # 1) 预计算 LUT
    LUT = np.zeros((M, K))
    for m, Cm in enumerate(codebooks):
        vm = y[m*d:(m+1)*d]
        LUT[m] = ((Cm - vm) ** 2).sum(axis=1)
    # 2) 累加得到近似距离
    dists = LUT[np.arange(M)[:,None], database_codes.T].sum(axis=0)
    return dists

四、优缺点 & 适用场景

优点

  • 存储压缩率高：128d float32 → 8B (64×)
  • 查询极快：LUT 预计算后每条向量只需 M 次加法
  • 与 IVF/HNSW 正交，易组合成 IVF-PQ、HNSW-PQ
  • 无需保留原始向量

缺点

  • 假设子空间独立，若维度间强相关，误差偏大 → OPQ 解决
  • 召回率受 M 和 K 影响，压缩越狠精度越差
  • 对稠密浮点向量有效，稀疏向量效果差
  • 需要训练阶段学码本
适用场景：大规模稠密向量检索 (>10⁶)，图片/文本 embedding 检索，作为 IVF/HNSW 的量化后端。工业界代表：Faiss IndexPQ, Faiss IndexIVFPQ。

五、与其他量化方法对比

方法压缩率误差适用

常见误区

  • D 必须整除 M：例如 D=128 时 M 只能取 {1,2,4,8,16,32,64,128}，不能取 20 或 12。选参数前先分解 D 的因子。
  • K=256 是特殊值：log₂256 = 8 bit = 1 字节，正好对齐字节存储。K=200 需要 8 bit 存储但浪费 56 个编码空间；K=300 则需要 9 bit，跨字节对齐困难，SIMD 效率下降。
  • M 越大不一定误差越小：总比特预算 = M × log₂K。M 从 8 涨到 16 但 K 从 256 掉到 16（保持字节数相同），每段太粗反而误差上升。经验：优先 K=256 固定，再调 M。
  • 子空间独立性假设：PQ 把 D 维切成不相干的 M 段，但真实数据的维度往往相关（例如深度学习 embedding 前后段有耦合）。方向错位时误差大，此时用 OPQ 先旋转再切段。
下一步学什么？
  • 10 亿向量还嫌慢 → IVF-PQ：先粗聚类分桶，只扫 nprobe 个桶，扫描量降到 1%。
  • PQ 精度不够（子空间强相关）→ OPQ：先学一个正交旋转 R 让各段能量均衡，同码率下误差再降 5~15%。
  • 更进一步 → RaBitQ / ScaNN（各向异性量化，2023 起最新一代）。
