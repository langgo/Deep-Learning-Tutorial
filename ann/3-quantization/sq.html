SQ · 标量量化 (Scalar Quantization)

最朴素的向量压缩：逐个数字量化到低比特整数 —— 简单、快、误差可控，是所有量化方案的基线。

前置阅读： 前置：无 · 这是本类别入门 建议顺序：SQ (当前) → PQ → IVF-PQ → OPQ
关键术语速查（点击展开）
量化 (Quantization)
把连续/高精度数值映射到少量离散取值，用精度损失换存储空间。
bucket（桶）
量化后所有可能落入的离散取值之一。b 比特量化共有 L = 2b 个桶。
min-max 量化
用数据的最小值和最大值确定量化范围，把 [min, max] 均匀切成 L 段。实现最简单。
quantile 量化（等频桶）
让每个桶包含相同数量的数据点，桶宽按数据密度自适应变化。对长尾分布更友好。
clip（截断）
数据超出量化范围时直接压到边界值，防止越界。用来抵抗极端离群点。
MSE（均方误差）
Mean Squared Error，衡量量化重构值 x̂ 与原值 x 的平均平方偏差。
SIMD（单指令多数据并行）
CPU 一次指令对多个数据同时运算。int8 SIMD 距离计算通常比 float32 快 4~8 倍。
新手引导 · 建议按顺序体验：
  1. 先在"交互式演示"里选一个分布（正态 / 长尾偏态 / 双峰），看直方图形状。
  2. 把 bit-width 从 8 拉到 2，观察量化桶红点从密变疏。
  3. 观察 MSE / 最大误差 指标随比特下降迅速上升。
  4. 在 2D 演示区点击不同位置作为查询点，观察 量化后 top-10 是否与真实 top-10 翻转。

一、直观理解

类比：把体温度数从"36.578" 简写成"37"

你测体温得到 36.578°C，实际记录时说"36.5°C" 或"37°C" 也够用 —— 精度损失了一点但节省纸张。SQ 就干这事： 把 float32 (32 bit, 4 字节) 换成 int8 (8 bit, 1 字节)，一个数字压缩 4 倍。128 维向量从 512 字节压到 128 字节。

  • 逐维度独立操作 (与 PQ 的"分段找码本"不同，SQ 就是把每个数字取整)
  • 无需训练码本 (min/max SQ 只需扫一遍数据取范围)
  • 解码 = 反向线性映射，一次浮点乘法就能还原

SQ vs PQ 的差别

SQ (int8)PQ (M=8, K=256)
压缩单位每维 (标量)每段 d 维子向量
码本无 (只需 min/max)M × K 个中心
压缩率4× (float32→int8)64× (128→8B)
误差小 (0.4% ~ 2%)大 (5% ~ 20%)
训练秒级 (扫一遍)分钟级 (M 次 K-Means)

二、算法原理

符号速查表

符号含义典型取值

本页统一基线：下文分析和存储对比均以 D = 128, N = 100 万 为例。原始 float32 存储 = 128 × 4 × 106 = 512 MB。

2.1 均匀量化 (Uniform SQ)

对每维 j，扫描数据得到 minj 和 maxj (或全局共用)。用 b 比特把 [min, max] 均匀切成 L = 2b 份。

q(xj) = round( (xj − minj) / (maxj − minj) · (L − 1) )
x̂j = minj + q(xj) · (maxj − minj) / (L − 1)

典型 b=8 (int8, L=256)：4× 压缩，误差 ≈ 范围 / 512。

2.2 分位数 (Non-uniform / Quantile SQ)

均匀量化在数据长尾时浪费桶。改进：让每个"桶"包含相同数量的数据 (等频)，或参考直方图找最佳边界。 SQ-fp16 是极简版：直接用 16 位半精度浮点保存，无量化桶概念但省一半空间。

2.3 分布参数量化 (SQ-mean-std)

假设数据近似正态分布，用 μ ± Kσ 作为量化范围 (K=3~4 覆盖 99.7%)，越界值 clip：

q(xj) = clip(round((xj − μj) / σj · S), −(L/2), L/2 − 1)

比 min-max 更鲁棒 (对少数极端值不敏感)。

2.4 编码/解码流程

def train_sq(X, bits, mode='minmax'):
    D = X.shape[1]
    L = 2 ** bits
    params = {}
    if mode == 'minmax':
        params['min'] = X.min(axis=0)   # (D,)
        params['max'] = X.max(axis=0)
    elif mode == 'meanstd':
        params['mean'] = X.mean(axis=0)
        params['std'] = X.std(axis=0)
    params['L'] = L
    return params

def encode(x, params, mode='minmax'):
    L = params['L']
    if mode == 'minmax':
        norm = (x - params['min']) / (params['max'] - params['min'])
        q = np.clip(np.round(norm * (L - 1)), 0, L - 1).astype(np.int32)
    else:
        norm = (x - params['mean']) / (params['std'] + 1e-9)
        q = np.clip(np.round(norm * (L / 8) + L / 2), 0, L - 1).astype(np.int32)
    return q

def decode(q, params, mode='minmax'):
    L = params['L']
    if mode == 'minmax':
        return params['min'] + q / (L - 1) * (params['max'] - params['min'])
    else:
        return params['mean'] + (q - L / 2) / (L / 8) * params['std']

2.5 距离计算

解码后按 float32 常规计算，或直接在整数域上做 (Faiss ScalarQuantizer 支持 SIMD int8 加速)。
误差期望值 (均匀 SQ, 均匀分布)：MSE ≈ Δ²/12，其中 Δ = 桶宽。

直觉：为什么误差是 Δ²/12？

把量化想象成"四舍五入到最近的桶中心"。如果原始值 x 在桶宽 Δ 内均匀分布，那么误差 e = x − x̂ 也在 [−Δ/2, +Δ/2] 均匀分布。均匀分布的方差是 (b−a)²/12 = Δ²/12。这就是均匀量化的理论误差下界——只要数据近似均匀落在每个桶里，就无法比这个再小了。

推论：每加 1 bit → L 翻倍 → Δ 减半 → MSE 变为 1/4。所以 8→4 bit 误差涨 16×，4→2 bit 再涨 16× —— 低比特下误差爆炸就是这条曲线。

四、优缺点 & 适用场景

优点

  • 实现极简，无需 K-Means 训练
  • 解码开销极小，一次线性映射
  • SIMD 友好 (int8 加速比 float32 快 4~8×)
  • 可与任意索引组合 (SQ + IVF + HNSW)

缺点

  • 压缩率有限 (最多 8× / int4)
  • bit 数越低误差急剧上升
  • 对偏态/多峰分布效果差 (min-max 浪费桶)
  • 不能像 PQ 一样用 LUT 完全跳过原向量
工业实践：Faiss IndexScalarQuantizer, ES hnsw + int8, PGVector halfvec/bit。作为"低成本高召回"方案先用 SQ，再看是否需要 PQ 进一步压缩。

常见误区

  • per-dim vs global min/max 差别巨大：每维独立取 min/max 比整体共用一组参数误差小得多，但要存 2D 个参数（D=128 时 = 256 float）。工业实践一般选 per-dim。
  • 长尾分布下 min-max 浪费大部分桶：极端离群点把范围拉宽，中间稠密区域只用到少数几个桶。此时切到 quantile 或 mean-std 模式（在演示中拉动"数据分布 → 长尾偏态"看效果）。
  • int8 时 top-1 可能与 float32 不一致：SQ 压缩后近邻排序会被扰动。安全做法：SQ 只作为 ANN 粗排（返回 top-100），再用原始 float 精排 top-10。
  • 不要用极小 b（1~2 bit）做距离排序：桶太粗导致大量点撞进同一个桶，任意排序都退化到随机。1-bit SQ 更适合作为哈希键。
下一步学什么？
  • SQ 4× 压缩不够 → PQ · 乘积量化 可以再压 8~16 倍（总 64× 压缩），但需要训练码本。
  • 亿级向量还嫌慢 → IVF-PQ 加入倒排索引，只扫少量分桶。
  • PQ 误差偏大（维度间相关）→ OPQ 先旋转再量化，同码率下再降 5~15% 误差。
