HNSW - Hierarchical Navigable Small World

分层可导航小世界图 — 当前工业界最主流的近似最近邻算法（Faiss、Milvus、Qdrant、Weaviate、pgvector 都采用）

前置： 邻近图基础 贪心搜索 跳表（推荐了解）
建议顺序： HNSW (当前) → NSG → DiskANN → SPANN
关键术语速查（点击展开/折叠）
邻近图（proximity graph）
每条边连接空间中"距离较近"的一对点。ANN 图索引就是在这类图上做贪心导航。
贪心搜索
每一步走到"当前节点邻居中距离目标最近"的那一个，直到没有更近的邻居。
beam search（束搜索）
贪心的推广：不是只保留当前最近的 1 个点，而是同时保留 ef 个候选，一起向邻居扩展。ef 越大越不容易陷入局部最优。
entry point（入口点 EP）
查询开始的节点。HNSW 里 EP 是最高层唯一存在的那个点。
level（层）
每个节点被随机分配一个层号 l；节点会存在于 Layer 0..l 的所有层。
跳表（skip list）
多层链表结构：上层稀疏、下层密集。HNSW 是跳表在图上的推广。
efConstruction / efSearch
构建时 / 查询时的候选队列大小。越大质量越高、越慢。
M
每层每个节点保留的最大邻居数（Layer 0 通常允许 2M）。
几何分布
抛硬币直到出现正面的次数分布。HNSW 用 l = ⌊-ln(uniform) · mL⌋ 采样，等价于几何分布，越高层节点越少。

一、直观理解：类比跳表

本方案解决了什么问题： IVF/PQ 类倒排索引在千万级向量上召回受限；HNSW 用"分层图 + 贪心导航"把查询复杂度降到 O(log N)，同精度下比 IVF 快 5~10×。 如果不熟悉"邻近图"或"贪心搜索"概念，可先看本目录 上级导航 中的基础章节。

HNSW 由 Yury Malkov 于 2016 年提出，是图索引 ANN 的里程碑。它的核心思想借鉴了跳表（Skip List）：

跳表回顾： 有序链表中查一个值需要 O(n)。跳表在原始链表之上加多层"稀疏"链表，每一层跨度更大。查询时先在顶层做"大跳"，再逐层下降精修，最终降到 O(log n)。
HNSW 的类比： 底层（Layer 0）是完整的 NSW 图，包含所有 N 个点，边只连近邻。往上每一层随机保留少量节点，扮演"高速公路"。查询时从顶层入口开始贪心走，一路"缩小范围"，走不动了下降一层，最终在底层做精细的 beam search。
为什么快？ 顶层稀疏但跨距大，几步就能跳到"目标区域附近"；底层稠密但只需局部搜索。整体查询复杂度 O(log N)。

层数按指数分布随机决定：约 1 / ln(M) 的概率进入更高层。所以底层几乎所有点，顶层只有个位数节点。

直觉：为什么用几何分布采样层数？

每往上一层，节点数量减少一个固定比例（≈ 1/M）。数学上这是几何分布：一枚硬币重复抛，第一次正面出现的次数。

实现上，HNSW 从均匀分布 u ~ U(0,1) 采样后取 -ln(u)，得到指数分布，再乘 mL = 1/ln(M) 并取下整——这个连续版本四舍五入后就是几何分布。

结果：Layer 0 有 N 个点，Layer 1 约 N/M，Layer 2 约 N/M²……顶层通常只有 1~几个节点，天然形成"高速公路"。

直觉：贪心 vs. beam search（束搜索）

纯贪心只保留"当前最近的 1 个候选"，容易陷入局部最优——想象山谷里的小坑，你走进去出不来。

beam search 同时保留 ef 个候选，每次扩展所有候选的邻居，直到 没有比当前 ef 个更近的新邻居 才停。相当于同时探索多条可能路径，容错更强。

HNSW 上层用 ef=1（快速大跳），Layer 0 用 ef=efSearch（精修）。

二、算法原理

2.1 图构建规则

  • M：每个节点在每层保留的最大邻居数（底层通常允许 2M）。
  • M_max：每层最大邻居数上限，防止 hub 过度连接。
  • efConstruction：构建时候选队列大小。越大质量越高、构建越慢。
  • mL = 1 / ln(M)：新节点采样层数用 l = ⌊-ln(uniform) · mL⌋。
  • 选边启发式（select-neighbors-heuristic）：不是简单选 M 个最近的，而是保证多样性——如果候选 v 相对已选邻居更近，则跳过 v，避免"聚集"，保留"长跳边"。

2.2 查询流程（Search）

  1. 从顶层入口点 ep 开始，贪心搜索 ef=1，找到该层最近点。
  2. 把该点作为下一层入口，重复直到 Layer 1。
  3. 在 Layer 0 做 ef=efSearch 的 beam search，返回 top-k。

2.3 伪代码

function INSERT(q, M, efConstruction, mL):
    l = ⌊-ln(random()) · mL⌋       # 新节点层数
    ep = entry_point
    for lc from L..l+1:
        W = search_layer(q, ep, ef=1, lc)
        ep = closest(W, q)
    for lc from min(L, l)..0:
        W = search_layer(q, ep, ef=efConstruction, lc)
        neighbors = select_heuristic(q, W, M)
        for e in neighbors:
            add_edge(q, e, lc)
            # 双向连边并裁剪
            if len(e.neighbors) > M_max: prune(e, lc)
        ep = W
    if l > L: entry_point = q; L = l

function SEARCH(q, k, efSearch):
    ep = entry_point
    for lc from L..1:
        W = search_layer(q, ep, ef=1, lc)
        ep = closest(W, q)
    W = search_layer(q, ep, ef=efSearch, lc=0)
    return top-k of W

function SEARCH_LAYER(q, ep, ef, lc):
    visited = {ep}; C = min-heap; W = max-heap
    push(C, ep); push(W, ep)
    while C not empty:
        c = pop_min(C)
        f = top(W)
        if dist(c,q) > dist(f,q): break
        for e in neighbors(c, lc):
            if e in visited: continue
            visited.add(e)
            if dist(e,q) < dist(f,q) or |W| < ef:
                push(C, e); push(W, e)
                if |W| > ef: pop_max(W)
    return W

2.4 选边启发式（select-neighbors-heuristic）

论文中最关键的 trick。对于候选集 C（按距 q 排序），从近到远考察每个 v：

  • 如果已选邻居中存在 u 使得 d(u, v) < d(q, v)，说明 v 到 q 的方向已有 u 覆盖，跳过 v。
  • 否则选入 v。

直观上，这个规则保留了不同"方向"的邻居，避免图被局部团结构主导，保持了图的可导航性。

图示：为什么要"保留方向多样性"？

想象 5 个候选邻居围绕节点 p：如果 v₂ 很靠近 v₁ 且都在 p 的同一侧，那么只保留 v₁ 就足够——v₂ 提供的方向已经被 v₁ 覆盖。删掉 v₂ 可以让剩下的边覆盖其它"方向"，避免所有邻居挤在同一片区。

六、优缺点 & 适用场景

优点

  • 召回高同精度下比 IVF 快 5-10 倍
  • 增量友好支持在线插入（不像 IVF 需重训 k-means）
  • 参数直观M / ef 意义清晰
  • 无需训练无 k-means 训练阶段

缺点

  • 内存重整图必须驻留内存
  • 删除慢删除需要标记 + 定期重建
  • 构建慢大数据集构建时间线性于 N log N
  • 分片难跨机分布式版本尚不完美

适用场景

  • 数据规模：百万至亿级向量
  • 召回要求高（> 95%）
  • 查询延迟敏感（毫秒级）
  • 数据基本不删除，主要是追加

常见误区

  1. 层数越多不一定越快：顶层过稀（甚至只剩 1 个点）时，"大跳"步长其实退化，跳不到目标区域附近，反而浪费时间。
  2. M 越大不一定越好：M 决定内存和构建速度；M=64 相较 M=16 内存 4×、构建时间 3~4×，但召回提升有限。
  3. efConstruction 太小图质量差：构建期候选池不足会导致邻居选得偏，后期 efSearch 再高也救不回来。生产上 efConstruction ≥ 100。
  4. 不适合超大规模：内存受限（10 亿 128 维 ≈ 500GB），单机装不下；此时应考虑 DiskANN / SPANN。

下一步学什么

  • → NSG：单层图，省内存 30%~50%，同精度下缓存更友好
  • → IVF-HNSW：大规模场景（10 亿+）用 IVF 粗筛 + HNSW 精修 + PQ 压缩
  • → DiskANN：图存 SSD 的方案，先看 NSG 再看它更顺
