NSG / NSSG - Navigating Spreading-out Graph

单层的可导航图 — Fu 等人（浙江大学 & 阿里巴巴）2019 年发表于 VLDB 的图索引方法。核心贡献：MRNG 选边规则 + Navigating Point 入口

前置： HNSW（必读，理解多层图）
建议顺序： HNSW → NSG (当前) → DiskANN → SPANN
关键术语速查（点击展开/折叠）
MRNG（Monotonic RNG）
NSG 使用的选边规则。保证任意源节点到任意查询点存在单调路径：沿路走距离目标点距离单调递减。
RNG（Relative Neighborhood Graph，相对邻近图）
经典邻近图：边 (u, v) 存在 ⇔ 不存在第三点 w 使得 d(u,w) < d(u,v) 且 d(v,w) < d(u,v)。RNG 图稀疏但可导航性差，MRNG 是其改进。
Navigating Point（导航点）
NSG 图的唯一入口，通常是数据集的 medoid（质心最近的实际点）。所有查询从这里出发。
medoid（中位点）
数据集里距离全体质心最近的实际数据点。相对 centroid（连续质心），medoid 一定在数据集中。
KGraph（初始 KNN 图）
NSG 构建的第一步：先近似算出每个点的 top-K 邻居图。作为 MRNG 选边的候选池来源。构建成本大（O(N1.14)）。
lune（月牙）
两个圆的交集区域。MRNG 里定义为：以 p 为圆心 R=|pv|、以 v 为圆心 R=|pv| 的两圆交集——即"同时比 p 近、又比 v 近"的点集合。
单调路径
从任意起点走到目标 q 的一条路径，路径上每一步到 q 的距离严格递减。MRNG 保证这样的路径存在，因此贪心永远不会"绕远"。
新手引导（按顺序操作）：
  1. 先切到【MRNG 规则详解】Tab，点【播放规则演示】—— 理解为什么某些邻居会被剪掉（月牙 lune 里存在已选邻居 u）
  2. 切到【构建 NSG】Tab，点【构建 NSG】按钮，观察 KGraph → 选边 → DFS 连通 的过程
  3. 切到【查询演示】Tab，点画布任意位置作为查询点，看从 NP（Navigating Point）出发的单层贪心搜索
  4. 调 R / L 观察图密度与召回的权衡

一、直观理解：为什么单层？

本方案解决了什么问题： HNSW 用多层图承担"从远到近"的导航，代价是每个上层节点都要额外的边和内存。NSG 换思路——若图本身就"处处可导航"，就不需要多层。
如果不知道 HNSW 是什么，请先看 HNSW 页面。

HNSW 用多层来加速"从远到近"的导航，NSG 换了个思路：如果单层图本身就"可导航"，就不需要多层。可导航的意思是：从任意节点出发，通过贪心走邻居，能收敛到查询点的真正最近邻。

类比： 想象一张城市地图。HNSW 像"高速+省道+县道"三层网络；NSG 像一张"精心规划的道路网"——每个路口的道路方向经过设计，从任何地方出发按"离目的地更近"的方向走都能到。
类比 2： RNG（Relative Neighborhood Graph，相对邻近图）保证图连通且无冗余边，但可导航性差。MRNG（Monotonic RNG）做了改进：对每个节点 p 和目标 q，都存在一条 单调递减距离 的路径。NSG 用 MRNG 的近似作为图。
核心思想： 好的图 = 少的边 + 正确方向。NSG 的选边规则同时实现"稀疏"和"覆盖所有方向"。

直觉：什么叫"单调路径"？

任给起点 s 和目标 p，存在一条依次经过若干中间点的路径 s → x₁ → x₂ → ... → p，且每一步到 p 的距离都严格变小——永远不"绕远"。

这在 MRNG 图上有理论保证：贪心搜索永远不会走冤枉路，因此单层单入口的贪心也能收敛到真最近邻。

二、算法原理

2.1 构建三步

  1. Init Graph：先用 KGraph（近似 KNN graph）作为初始图。
  2. 选 Navigating Point：全体数据的质心（centroid）位置最近的点，作为唯一入口。
  3. MRNG Edge Selection：从每个节点出发做贪心搜索得到候选集，用 MRNG 规则筛选出 R 条边。
  4. DFS Connect：如果图不连通，从 navigating point 做 DFS，遇到不可达连通分量就补边。

2.2 MRNG 选边规则（本页面核心演示）

规则： 对于节点 p，候选邻居 C 按距 p 升序处理每个 v ∈ C：
如果已选邻居 u 使得
 d(p, u) < d(p, v) 且 d(u, v) < d(p, v)
——即 u 落在 lune(p, v)（月牙形）区域内，则不选 v；否则选入。

lune 是什么： lune(p, v) 是以 p 为圆心 R=|pv| 的圆 与 以 v 为圆心 R=|pv| 的圆 的交集——也就是"既比 p 到 v 近、又比 v 到 p 近"的所有点。若这个区域里已经有一条选好的邻居 u，那么走 p→u→v 一定比直接 p→v 更好（两段都比一段短），所以 p→v 这条边冗余。

直观：如果去 v 的路径可以"经过 u 中转"（且中转比直达短），那 pv 这条边就冗余，删掉。这样每个"方向"最多保留一条边，保证多样性。

动画配色（对照下方交互）

右侧动画中：青色虚线圆 = 以 p 为圆心 R=|pv|；紫色虚线圆 = 以 v 为圆心 R=|pv|；两圆交集的浅蓝填充区 = lune(p, v)。

如果某个已选邻居 u 落在这个月牙里（红色光晕高亮），就会拒绝 v，并画一条红色虚线 u→v 表示"u 中转"。

2.3 查询流程

function SEARCH(q, k, L):
    candidates = priority_queue(size=L)
    push(candidates, navigating_point)
    while has_unvisited(candidates):
        p = pop_nearest_unvisited(candidates)
        mark p visited
        for e in neighbors(p):
            if e visited: continue
            push(candidates, e)     # 保留 L 个最近
    return top-k of candidates

比 HNSW 简单：只有一层、只有一个候选队列（beam）、只有一个参数 L 控制精度。

五、复杂度

指标值说明
构建时间O(N · L · R)需要预先算 KGraph，成本更高
查询时间O(L · R)单层贪心，每步扫描 R 邻居
内存占用N · R · 4 字节 + 向量比 HNSW 略少（无多层开销）
是否可导航是（近似 MRNG）MRNG 图保证任意节点单调路径

六、优缺点 & 适用场景

优点

  • 图小比 HNSW 边数少 30%~50%
  • 查询快同精度下 CPU 缓存友好
  • 单一入口无需多层维护
  • 理论保证MRNG 有可导航性证明

缺点

  • 构建重依赖 KGraph 预处理
  • 难增量不擅长在线插入
  • 全量重建数据变化需重建 KGraph
  • 工业化比 HNSW 少

适用场景

  • 静态数据集（一次构建、多次查询）
  • 对内存带宽敏感的场景（图小 = cache miss 少）
  • 科研 / benchmark 环境

常见误区

  1. MRNG 保证单调路径但不保证是最短路径：贪心不会走"回头路"，但也不代表跳数最少；有时会绕一大圈到达。
  2. 构建极慢：KGraph 初始化本身要 O(N1.14)。生产上百亿数据集通常等一整天。
  3. 不友好的动态更新：MRNG 边选依赖全局邻居分布，插入/删除后局部邻居会打破单调性——通常做法是攒批后离线重建。
  4. 只有单入口：Navigating Point 若被删除或分布极端不均，全图查询都受影响；这也是 SPTAG/DiskANN 用 medoid 但辅以图导航的原因。
