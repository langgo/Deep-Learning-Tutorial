关键术语速查（点击展开）
Jaccard 相似度
两个集合的交集除以并集，J(A,B) = |A ∩ B| / |A ∪ B|，范围 [0,1]。
shingle
k-gram 滑动子串。把文本按 k 个字符一组切成一堆重叠的短片，用来把"文档"变成"集合"。
排列 π
对全集元素做一次随机重排，把每个元素都重新编号，用来定义 MinHash。
签名（signature）
每个集合用 k 个哈希函数各取一个 min 值，得到长度为 k 的整数向量，就是这个集合的"MinHash 签名"。
band
把签名按行切成 b 段，每段包含 r 行。每一 band 单独当哈希键分桶。
S-curve
候选概率 1−(1−Jr)b 随 Jaccard 变化的 S 形曲线：低相似段几乎不命中，高相似段几乎必命中。
LSH banding
把签名切 band + 每 band 分桶的整套流程，让 MinHash 从"逐对比较"降到"亚线性检索"。
新手怎么玩这个页面？
  1. 修改集合 A、B 的文本，看它们的 shingle 集合怎么变。
  2. 观察绿色 chip：那些是 A、B 共有的 shingle，越多说明真实 Jaccard 越高。
  3. 把 k 从 4 拉到 60，观察 MinHash 估计逐渐逼近真实 Jaccard（方差 ~ 1/k）。
  4. 调整 bands b，观察 S-curve 的拐点 t* ≈ (1/b)1/r 左右移动。

1. 直观理解：抽签选代表

假设你手上有两袋糖，每袋里有几十种颜色的糖果。要判断两袋糖有多相似，直接算 交集 / 并集（也就是 Jaccard 相似度）当然可以，但集合一大就慢了。

MinHash 的思路：用一个统一的随机顺序为每种糖果编号，问"每袋糖里编号最小的那颗是啥？" 如果两袋糖内容差不多，那么它们"最小编号糖果"很可能是同一种；反之则不同。

神奇的性质：

Pr[MinHash(A) = MinHash(B)] = |A ∩ B| / |A ∪ B| = Jaccard(A, B)

只用一次 Min 就能拿到 Jaccard 的无偏估计！用 k 个独立的随机顺序，取平均即可把方差缩到 J(1-J)/k。这就是 MinHash 的全部魔法。

2. 算法原理

2.0 符号速查表

符号含义
k哈希函数（也就是签名长度）个数，越大估计越准
bband 数量，把签名切成多少段做 LSH 分桶
r每 band 的行数，满足 b · r = k
π作用在全集 U 上的一次随机排列
hi第 i 个哈希函数，用来近似模拟第 i 个随机排列
si集合 S 在 hi 下的最小值，即签名向量的第 i 位
J真实 Jaccard 相似度
t*S-curve 拐点，t* ≈ (1/b)1/r

2.1 Jaccard 相似度回顾

J(A, B) = |A ∩ B| / |A ∪ B|

范围 [0, 1]；1 表示完全相同，0 表示完全不相交。

2.2 MinHash 定义

选一个作用在全集 U 上的随机排列 π：U → U。则

hπ(S) = min{ π(x) : x ∈ S }

2.3 全文最关键的一步：为什么"最小值 = Jaccard"？

这是 MinHash 全部魔法的来源，请务必花两分钟看懂。

准备场景：把 A ∪ B 里所有元素排成竖直一列，每个元素在这一列里的位置由随机排列 π 决定。也就是说，每个元素都被随机地扔到列的某一行，行号就是它的"编号"。

问一个问题："这一列从上往下数，第一个属于 A 的元素是谁？"记它为 a*。它就是 min π(A) 对应的元素，也就是 MinHash(A)。同理 b* = MinHash(B)。

什么时候 MinHash(A) = MinHash(B)？当且仅当 a* = b*，也就是说"A ∪ B 里排名最靠前的那个元素，同时属于 A 和 B"，也就是"排名最靠前的元素落在 A ∩ B 里"。

算概率：因为 π 是均匀随机排列，"A ∪ B 里排名最靠前的元素"是等概率地从 A ∪ B 中任选一个。它恰好落在 A ∩ B 的概率就是

Pr[排名第一的元素 ∈ A ∩ B] = |A ∩ B| / |A ∪ B| = J(A, B)

所以

Pr[MinHash(A) = MinHash(B)] = J(A, B)

只用一次 min，就得到 Jaccard 的一个无偏 0/1 采样！用 k 个独立的随机排列，取"相同格子的比例"作为估计，方差就是 J(1−J)/k。这也是为什么 k 越大越准。

2.4 用哈希函数替代显式排列（工程实现）

直觉铺垫：真正的随机排列 π 太贵——需要存 |U| 个位置。工程上我们用简单的线性哈希 h(x) = (a·x + b) mod p 来近似模拟一个均匀随机排列，误差在实践中可以忽略。

h(x) = (a · x + b) mod p     (a, b 从 [1, p) 随机取，p 为大素数)

把 minx∈S h(x) 当作近似 MinHash。理论上这只是"近似"的排列，但在实践里质量很好。

2.5 Signature 矩阵

对每个集合 S，用 k 个独立哈希函数得到长度 k 的 签名向量。所有集合的签名并列组成一个 k × N 矩阵。相似的两列签名向量在很多行上会数值相同。

2.6 LSH Banding：从 signature 到候选对

先文字讲一遍：假设我们有 k = 12 行签名，选 b = 3、r = 4，那就是"把 12 行签名切成 3 段，每段 4 行"。每段（band）单独当作一个哈希键：把 band 内的 4 个数字拼字符串再哈希一次，落到同一个桶的两个集合就成为候选对。

示意：

签名（12 行）    切成 3 个 band（每 band 4 行）
   s1                ┐
   s2                │  Band 0 → 拼串哈希 → 桶键 0
   s3                │
   s4                ┘
   s5                ┐
   s6                │  Band 1 → 拼串哈希 → 桶键 1
   s7                │
   s8                ┘
   s9                ┐
   s10               │  Band 2 → 拼串哈希 → 桶键 2
   s11               │
   s12               ┘
  • 两列在 某个 band 完全相同 ⇒ 视为候选对
  • Pr[候选] = 1 − (1 − Jr)b（经典 S-curve）
  • 让"S-curve"的拐点落在你希望的相似度阈值 t*：t* ≈ (1/b)1/r
  • 调参口诀：b 越多、r 越小 → 拐点左移（更宽松，召回更多候选）；b 越少、r 越大 → 拐点右移（更严格，只挑高相似的）。

2.7 伪代码

输入：文档集合 D₁, D₂, ..., D_n；参数 k, b, r（k = b·r）
预处理：
  1. 对每个文档做 shingling（如 3-gram 字符或分词）→ 集合 S_i
  2. 随机采样 k 组 (a_j, b_j)，构造 h_j(x) = (a_j·x + b_j) mod p
  3. 对每个 S_i，计算签名 sig_i[j] = min_{x∈S_i} h_j(x)
查询/去重：
  1. 把 sig 分成 b 个 band
  2. 每个 band 做一次哈希桶（band 内的向量拼字符串再哈希）
  3. 落到同一个桶的一对文档 → 候选
  4. 对候选精确计算 Jaccard，做最终过滤

4. 案例逐步讲解

以默认输入为例：

  • A = "the quick brown fox jumps over the lazy dog" → 3-gram shingling 后约 40 个片段
  • B = "a quick brown fox leaps over the lazy dog" → 与 A 大部分 shingle 重叠
  • 真实 Jaccard ≈ 0.7~0.8（视 shingle 大小而定）
  • 用 k=12 个哈希函数得到长度 12 的签名，落在相同格子的比例约为 8-10 / 12 → MinHash 估计 ≈ 真实 Jaccard
  • 切成 b=4 band、r=3 rows：1 − (1 − 0.75³)⁴ ≈ 0.88，说明相似度 0.75 的两文档有约 88% 概率被送入候选

试着修改 A/B 文本、增大 k 观察估计变得越来越稳，或减小 b/增大 r 观察 S-curve 变陡（更严的相似度门槛）。

5. 复杂度 & 精度权衡

指标值说明
Signature 计算O(k · |S|)每个哈希扫一遍集合
存储签名O(k) 每文档k 通常 100~200，比原文档小得多
估计方差Var = J(1−J) / kk 越大越准
LSH 拐点t* ≈ (1/b)1/rb↓ 或 r↑ → 拐点右移（更严）
候选查询≈ O(b) 次哈希桶查询桶粒度取决于 r

6. 优缺点 & 适用场景

优点缺点
MinHash
  • Jaccard 相似度的无偏估计
  • 签名尺寸远小于原文档
  • 可分布式（每个 hash 独立）
  • 与 LSH banding 天然结合
  • 只对 Jaccard / 集合相似度有效
  • 对稠密向量（欧氏 / 余弦）不适用
  • 估计误差 ~ 1/√k
  • Shingling 选择影响很大

典型场景：大规模网页 / 新闻去重（Google, Bing）、爬虫 dedup、抄袭检测、Recommendation 中的 item-item 相似召回、日志异常子序列聚类。

常见误区

  • shingle 太小 → 假阳性激增。用 1-gram（单字符）会让几乎所有中文文档都共享大量单字，Jaccard 严重虚高。中文经验值 3~5-gram，英文 5~9-gram。
  • b · r 必须 ≤ k，且通常应恰好等于 k。不能超过签名长度，否则某些 band 会引用到"越界"的行。工程上要在 UI/参数里显式保证 b · r = k。
  • k 个哈希必须真正独立（不同 seed）。如果偷懒用同一个 seed 让 k 个 min 都一样，方差不会随 k 减小，估计毫无意义。
下一步学什么？
  • Classic LSH — 如果你要做欧氏/余弦距离检索，换那一族哈希。
  • SimHash — 需要词频权重的文档指纹去重。
  • LSH Forest — 用可变前缀替代固定 band，自适应相似度分布。
  • Weighted MinHash — 元素带权重的场景（如加权集合、TF 特征）。
  • bottom-k MinHash — 只保留每个哈希下最小的 k 个元素，估计更稳。
