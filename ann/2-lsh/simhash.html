关键术语速查（点击展开）
汉明距离（Hamming distance）
两串等长二进制不同位的个数。SimHash 用汉明距离衡量两个指纹的接近程度。
指纹（fingerprint）
SimHash 的输出：一串 f 位（常见 64 位）二进制串，用来代表整篇文档。
加权符号哈希
每维加权投票，正数记 1、负数记 0。相当于按特征权重做一次"多数表决"。
分块索引
把 f 位指纹切成 c 块，用每一块当哈希键分桶。鸽笼原理保证真的重复项至少有 c − k 块完全一致。
鸽笼原理
如果两个指纹只差 k 位，把它们切成 c 块，最多有 k 块被影响 → 一定有 c − k 块完全一致。
cosine 与 π 的关系
随机超平面把两向量切开的概率恰好等于两向量夹角 θ 占 π 的比例：Pr = 1 − θ/π。这是 SimHash 局部敏感性的数学根基。

1. 直观理解：让相似文档留下相似"指纹"

MinHash 处理"集合"很擅长，但如果我们要考虑词频权重、短文档差异，就轮到 SimHash 出场了。

SimHash 是 Charikar 2002 年提出、Google 2007 论文《Detecting Near-Duplicates for Web Crawling》推广的技术。它做一件事：把任意长度的文档压缩成一个 f 位（通常 64 位）二进制指纹，让相似文档产生只有几位不同的指纹。

类比：想象每个词都在 f 维空间中投了一票（带权），最终每一维的正负号取决于"多数表决"。相似文档投票分布相近，指纹自然相近 → 用 汉明距离 比较即可判定重复。

  • SimHash 是 局部敏感 的：两文档余弦相似度越高，指纹汉明距离越小
  • Google 报告：对 8×10⁹ 网页，取 64 位指纹、汉明距 ≤ 3 判为重复，效果与准确度俱佳

2. 算法原理

2.0 符号速查表

符号含义
f指纹位数（常用 64）
k汉明距阈值，两指纹差 ≤ k 就算近似重复
c分块数，把 f 位指纹切成 c 块
θ两向量夹角（弧度），θ = arccos(sim)
wi特征 i 的权重（如词频、TF-IDF）

2.1 SimHash 步骤

输入：文档 D，位数 f（如 64）
1. 特征抽取：切词 / n-gram → 特征列表 {(token, weight)}
2. 初始化 v = [0.0] * f
3. 对每个特征 token：
     h = f-bit hash(token)         // 如 MurmurHash / SHA-1 高 f 位
     for i in 0..f-1:
         if bit_i(h) == 1: v[i] += weight(token)
         else:              v[i] -= weight(token)
4. 生成指纹 fp：
     fp_i = 1 if v[i] > 0 else 0
5. 输出 fp（f 位二进制串）

2.2 为什么是"局部敏感"的？

设两文档特征集合相似，改动一个词只会给某些维加/减一个小权重，不足以翻转"多数派"的符号 → 大部分 bit 保持不变。

直觉铺垫：更严谨地看，SimHash 等价于用 f 个随机超平面把加权特征向量"切开"。每个 bit 位就是"落在超平面哪一边"的 0/1 标签。随机超平面把两个向量切开的概率 = 两向量夹角占 π 的比例——夹角越小（向量越相似），越难被随机切开，指纹在这一位相同的概率就越高。

可以证明：对随机映射假设下，两文档余弦相似度 sim(A, B) 与它们指纹的相同位比例满足：

Pr[fpi(A) = fpi(B)] = 1 − θ(A, B) / π

其中 θ(A, B) = arccos(sim(A, B))。也就是说，越相似的文档指纹汉明距越小。

2.3 汉明距离阈值 & Google 分桶技巧

直觉铺垫：鸽笼原理。假设指纹总共有 k 位不同，把它切成 c 块，最坏情况这 k 个"不同位"都被分散到 c 块里；即便每一块都被至少 1 个"不同位"污染，也只能污染 min(k, c) 块。所以一定至少有 c − k 块完全一致。换句话说：只要 c ≥ k + 1，就至少有 1 块能作为"确定命中"的哈希键。

典型经验值：

  • f = 64，k = 3（近似重复 threshold）
  • 暴力比较 N 个指纹是 O(N²)；不可扩展
  • Google 的解法：把 64 位分成 c 块（如 c=4），如果两个指纹汉明距 ≤ k，那么至少存在 c − k 块完全一致；把每块作为哈希键分桶查找即可

4. 案例逐步讲解

以默认四个中文文档为例（f=32、3-gram + TF 权重）：

  • D1 vs D2：只替换了几个近义词（搜索→查找、桶里→桶中、映射→放到），大量 3-gram 相同 → 汉明距通常 < 3
  • D1 vs D3：都提到"哈希"但主题不同 → 汉明距在 8~14 之间
  • D1 vs D4：完全不同的主题 → 汉明距接近 f/2（≈16），说明"几乎独立"

把 f 调到 64 位、阈值设 3 就是 Google 论文的经典配置；把粒度切换成 字符 2-gram 会让指纹对短文档更敏感，但也更容易被噪声影响。

5. 复杂度 & 权衡

指标值说明
指纹生成O(|features| · f)每个特征更新 f 维累加器
存储O(f/8) Byte 每文档64bit → 8 Byte
暴力比对O(N²)不可扩展
分块索引比对≈ O(N · C(c, k) / 2^{f/c})k 是允许的汉明距

调参口诀：阈值 k 越小 → 判定越严；c 越大 → 索引越轻但每块越短、每桶命中越多。经验：f=64, k=3, c=4 是网页去重的黄金起点。

6. 优缺点 & 适用场景

优点缺点
SimHash
  • 指纹极小（8 Byte / doc）
  • 支持词频权重，效果比 MinHash 更精
  • 与 Google 分块索引结合可亚线性查询
  • 可流式增量（不需重排全集）
  • 对短文档鲁棒性较差
  • 阈值 k 需人工调
  • 受 tokenizer 影响明显
  • 非稀疏 & 长文档效果最好

典型场景：网页去重（Google 论文场景）、新闻聚合去重、Twitter/朋友圈"洗稿"检测、语料清洗，配合分块索引可以支撑百亿级文档规模。

常见误区

  • 短文本极不稳定。只有几十字的推文/评论，一个高权重词就能让某几位彻底翻转。工业界通常要求文档 ≥ 数百词，否则改用 MinHash 或 BM25。
  • tokenizer 换一种，指纹全变。字符 3-gram 和词级分词得到完全不同的特征分布，指纹不可跨系统比较。务必把分词方式当成"哈希盐"记下来，全流水线固定。
  • 停用词/高频词不处理，会让 "the / 的 / 是" 独占 top 权重，指纹被这些无信息词主导。上线前记得 IDF 打压或直接停用词过滤。
下一步学什么？
  • Classic LSH — 回看欧氏 LSH，理解 SimHash 只是随机超平面 LSH 的一种压缩形式。
  • MinHash — 集合场景的姊妹算法，理论保证更干净。
  • SpotSig — 结合停用词位置和 shingle 的改进版指纹，抗噪更强。
  • Weighted SimHash — 把 TF-IDF、位置权重一起塞进 SimHash。
  • 现代方案：SBERT + HNSW — 语义嵌入 + 图索引，对短文本和跨语言更友好，是当代去重推荐链路的默认起点。
