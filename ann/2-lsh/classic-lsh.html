关键术语速查（点击展开）
哈希族（hash family）
一组同构造的随机哈希函数，每次抽一个，用来对点进行"随机分桶"。
局部敏感（locality-sensitive）
相似样本以高概率被哈到同一个桶（"碰撞"），不相似的样本以低概率碰撞。
(r, cr, p₁, p₂)-sensitive
距离 ≤ r 的两点碰撞概率 ≥ p₁；距离 ≥ cr 的两点碰撞概率 ≤ p₂。这就是 LSH 的官方定义。
p-stable 分布
从中随机采样后做线性组合，结果仍服从同族分布。L2 距离对应高斯（2-stable），L1 距离对应柯西（1-stable）。
AND 组合
用 K 个哈希函数拼签名，只有 K 位都一样才算命中。命中概率变成 pK，让曲线更陡。
OR 组合
建 L 张独立哈希表，任意一张表命中即算候选。整体命中率变成 1−(1−pK)L，把陡曲线的高相似段抬回来。
S-curve
把 AND-K 与 OR-L 组合起来，碰撞概率随相似度呈 S 形跳变：低相似段几乎不命中，高相似段几乎必命中。

1. 直观理解：把相似的东西装进同一个抽屉

想象你在整理一堆彩色玻璃球。如果你按颜色抽屉分类，那么颜色相近的球（红-粉红、深蓝-浅蓝）大概率会被扔进同一个抽屉。查找和某个球最像的邻居时，只需检查那只抽屉，不必翻遍整间屋子。

LSH（Locality Sensitive Hashing） 就是这样一种"魔法哈希"：与传统哈希"尽量把冲突分开"相反，LSH 刻意让相似的点碰撞，让不相似的点分离。

  • 经典 LSH（基于随机投影 / p-stable 分布） 用于 欧氏距离 或 余弦距离。
  • 核心思想：随机切一刀（超平面 / 投影线），落在同一侧或同一 bucket 的点更可能靠得近。
  • 切多次（K 次），把签名拼起来 → 桶更精细；开多张哈希表（L 张） → 提高召回率。

2. 算法原理

2.0 符号速查表

符号含义
a随机高斯向量，用来把 d 维点投影到一根随机方向上
w桶宽，投影后每隔 w 切一段，w 越大桶越粗
b[0, w) 上的随机偏移，避免切割线固定在整数点
KAND 组合数量，一张表里堆叠 K 个哈希
LOR 组合数量，用 L 张独立哈希表
k要返回的近邻个数（top-k）
p₁相邻点（距离 ≤ r）在单次哈希下的碰撞概率下界
p₂远点（距离 ≥ cr）在单次哈希下的碰撞概率上界
r"近"的距离阈值
cr"远"的距离阈值，倍率 c > 1
φ(t)标准正态 CDF，用来推导 p-stable LSH 的解析碰撞概率

2.1 (r, cr, p₁, p₂)-sensitive 哈希族定义

直觉铺垫：想象一个哈希函数就像抽奖，我们希望相邻的两个人（距离 r 以内）抽到相同结果的概率高（≥ p₁），距离较远的人（距离 cr 以外）抽到相同结果的概率低（≤ p₂）。这个性质就叫"局部敏感"。

一个哈希族 H 是 (r, cr, p₁, p₂)-sensitive 的，当且仅当对任意 q, p：

d(q, p) ≤ r   ⇒   Pr[h(q) = h(p)] ≥ p₁
d(q, p) ≥ cr   ⇒   Pr[h(q) = h(p)] ≤ p₂

其中 c > 1，p₁ > p₂。这个"间隙"越大，LSH 家族越好用。

2.2 p-stable LSH 哈希函数（本页所用）

直觉铺垫：所谓 p-stable 分布，是指从中随机采样后做线性组合，结果仍属于同分布家族。高斯就是 2-stable 的（对应 L2 欧氏距离），柯西是 1-stable 的（对应 L1 曼哈顿距离）。所以对 L2 欧氏距离做 LSH，用高斯投影正好。

对于 L₂ 欧氏距离，Datar-Immorlica-Indyk-Mirrokni 2004 的 p-stable LSH 定义：

ha,b(v) = ⌊ (a · v + b) / w ⌋
  • a：从高斯分布 N(0, 1) 抽样的随机向量（对 L₂ 是 2-stable）
  • b：从均匀分布 U[0, w) 抽样的随机偏移
  • w：桶宽（越大越粗糙，越小越精细）

2.3 AND 与 OR 组合：放大间隙

AND 组合（K 个）：将 K 个独立哈希函数并置成一个 K 维签名 g(v) = (h₁(v), h₂(v), …, h_K(v))。两点必须 所有 K 位都相同才算碰撞。

Pr[碰撞] = pK

OR 组合（L 个哈希表）：构造 L 张独立的哈希表，只要在 任意一张 表中碰撞即视为候选。

Pr[至少一张表碰撞] = 1 − (1 − pK)L

直觉解释：pK 让曲线变陡（要求 K 次同时命中，非常严格，只有非常相似的点才扛得住），而 1 − (1 − pK)L 又把这条陡峭曲线的下沿抬起来（L 张表任一命中即可）——这个"先陡后抬"的组合，正是 LSH 的精髓，也是所谓 S-curve 的来源。

2.4 伪代码

输入：数据集 P，参数 K, L, w
构建：
  for i = 1..L:
    随机生成 K 个 (a_j, b_j) 对
    for v in P:
      sig = (h_1(v), h_2(v), ..., h_K(v))
      Table_i[sig].append(v)
查询 q：
  候选集 C = ∅
  for i = 1..L:
    sig_q = g_i(q)
    C ∪= Table_i[sig_q]
  返回 C 中距离 q 最近的 top-k

4. 案例逐步讲解：100 个 2D 点的碰撞概率

假设某两个点距离 d。对于 p-stable LSH，用高斯投影后再离散化，一次哈希碰撞概率的解析形式（简化后）为：

p(d) = 1 − 2 · Φ(−w/d) − (2 / √(2π)) · (d/w) · (1 − e−w²/(2d²))

其中 Φ 是标准正态 CDF。直觉：

  • d → 0 时 p → 1（几乎必然碰撞）
  • d → ∞ 时 p → 0（几乎不会碰撞）
  • w 越大，曲线越平坦（区分度差）；w 越小，曲线陡但短距离也难碰撞

5. 复杂度 & 召回率-精度权衡

指标值说明
构建时间O(N · K · L · d)d 是向量维度
索引空间O(N · L)每张表存 N 个 id
查询时间O(K · L · d + |C| · d)|C| 是候选集大小
召回率1 − (1 − p₁K)LK↑ → 精度↑ 召回↓；L↑ → 召回↑ 但内存和候选量↑

调参口诀：先按目标召回率求 p₁K，再由 1 − (1 − p₁K)L ≥ target_recall 反解 L。

6. 优缺点 & 适用场景

优点缺点
Random Projection LSH
  • 亚线性查询时间
  • 理论保证（(r, cr, p₁, p₂)-sensitive）
  • 可分布式（每张表独立）
  • 更新友好（增量插入桶）
  • 需要多张表 L，内存占用大
  • 调参 K/L/w 敏感
  • 召回率低于图索引
  • 高维稀疏数据表现不如 HNSW

典型场景：大规模欧氏 / 余弦相似度检索（图像特征、Word2Vec 向量、指纹）、亚线性重复文档检测（配合 MinHash）、大规模广告 / 推荐候选召回。

常见误区

  • K 太大 → 召回崩塌。K 决定一次命中要"K 位全对"，K 从 3 拉到 8，签名瞬间被切碎，即使最近邻也可能一位不合就掉队。要记得同时用 L 补救。
  • L 太大 → 内存爆炸。每张表都要存一份 N 个 id 的桶结构，L=50 就是 50× 索引成本，很快撑爆机器。
  • w 与数据尺度不匹配。如果数据方差是 100，却把 w=1，几乎每个点独占一桶，碰撞率趋近 0；反过来 w 太大又让所有点挤成一桶，失去区分度。先看数据的投影分布再选 w。
下一步学什么？
  • MinHash — 如果你的数据是集合（网页 shingle、用户点击集合），换个 LSH 家族。
  • SimHash — 如果你要做文档去重，加权指纹更省内存。
  • Multi-Probe LSH — 工业改进版，只用 1 张表也能取回相邻桶。
  • HNSW（在图索引章节）— 对比看看现代主流方案与 LSH 的差别。

交叉引用：如果你的数据是集合，请看 MinHash；如果是文档去重，请看 SimHash。
