IVF-HNSW / HNSW-PQ 混合方案

用 HNSW 加速 IVF 粗量化中心查找，再用 PQ 压缩候选点的距离计算 —— 大规模 ANN 的工业界主流方案

前置（必读）： IVF-PQ HNSW PQ residual 残差概念
关键术语速查（点击展开）
IVF（Inverted File Index，倒排索引）
先把向量空间用 KMeans 聚成 nlist 个桶（Voronoi 单元），查询时只扫描离查询最近的几个桶。等于"先分区再检索"。
HNSW（Hierarchical Navigable Small World）
多层邻近图，高层稀疏、低层稠密，从顶层往下贪心搜索，可以把 O(N) 的最近邻查找降到 O(log N)。
PQ（Product Quantization，乘积量化）
把 d 维向量切成 M 段子向量，每段独立用小码本（大小 k=256）编码，一个向量只需 M 字节（对比原始 4d 字节），压缩 ~30 倍。
residual 残差
数据点减去所在桶的质心：r = x - c。分布集中在 0 附近，方差更小，PQ 量化误差因此显著降低。
LUT（Look-Up Table，查找表）
查询到来时先算好 M×k 的距离表；每个候选点只需 M 次表查询 + M 次加法即可得到近似距离，对 SIMD 极其友好。
posting list（倒排链表）
属于同一桶的所有向量 id + PQ code 的集合。查询时只遍历命中的 posting。
Voronoi 单元
把空间按"离哪个质心最近"划分成的多边形区域，每个区域对应一个 posting。
nlist / nprobe
nlist = 桶数量（如 1 万 ~ 100 万）；nprobe = 每次查询要扫描的桶数（如 8 ~ 64）。nlist 越大桶越小、检索越快但训练/内存成本更高；nprobe 越大召回越高但延迟增加。
HNSW-M vs PQ-M（⚠️ 两个 M 含义完全不同！）
HNSW 的 M = 图中每个节点的度数上限（如 16、32），控制图连通度；PQ 的 M = 子向量段数（如 8、16、32），控制码字长度。调参别搞混。
新手引导 · 演示阅读顺序：本页有 3 个交互演示，建议按 A → B → C 顺序玩：
  • 演示 A（HNSW 找桶）：观察多层图如何比线性扫描更快找到 nprobe 个中心（第 3 节）。
  • 演示 B（PQ 桶内估距）：观察 LUT 表如何用 M 次查表 + 加法一次算出候选点的近似距离（第 4 节）。
  • 演示 C（端到端）：把前两步合并，观察一次完整查询的两阶段流水线（第 5 节）。

本方案解决了什么问题

痛点
纯 IVF 的粗量化要线性扫描 nlist 个中心（10 万级别时成瓶颈）；纯 HNSW 在 10 亿级数据上内存爆炸（每点 4d 字节原始向量 + 邻接表）。
别人的方案
IVF：中心暴力扫描；HNSW：所有原始向量常驻内存。两者各偏一端，都难以同时满足"大规模 + 高召回 + 低延迟"。
本方案关键 idea
用 HNSW 加速 IVF 的中心查找（把粗量化从 O(nlist) 降到 O(log nlist)），再用 PQ 压缩桶内的原始向量（占用降到 ~1/32），两者互补。
代价
需要多训练一个 HNSW（只在质心上，规模小）；需要多存 PQ 码本；参数变多（nlist / nprobe / HNSW-M / efSearch / PQ-M / PQ-k）都要一起调。

⚠️ 命名警告 —— 本页有两个 M，含义完全无关

  • HNSW 的 M = 图中每个节点的度数上限（常见 16、32），控制图密度与检索路径宽度。
  • PQ 的 M = 子向量段数（常见 8、16、32），控制码字长度与压缩比。

下方两个演示的参数面板里都有 M 滑块，调参时请看清标签（"HNSW M" vs "PQ M"）。

符号含义典型取值 / 说明
nlistIVF 桶数量 = 质心数1 万 ~ 100 万，经验值 ≈ 4·√N ~ 16·√N
nprobe每次查询扫描的桶数nlist 的 1% ~ 5%

1. 直观理解 —— 分层导航 + 精细量化

想象你要在一个大城市（1 亿个向量）里找一家餐厅（最近邻）。

  • 纯 IVF 方案：把城市划分为 nlist=10000 个片区（聚类中心 = 片区中心），查询时把这 10000 个片区的中心全部对比一遍找最近的几个，再去这些片区里精查。片区多了以后，"选片区"这一步本身就成了瓶颈。
  • 纯 HNSW 方案：直接在原始向量上建一张多层图，一次搜索。但索引占内存太大（每个点存 32 维原始向量 + 邻接表），10 亿点难以装下。
  • IVF-HNSW 混合：用 HNSW 来管理"片区中心"（数量少、内存友好），加速"选片区"；片区内的原始点则用 PQ 压缩到 1/32 大小，用查找表快速算近似距离。
比喻：先坐飞机（HNSW 图导航）到目标城市，再打车（PQ 快速估距）在城市里找到餐厅。飞机路径不需要覆盖每一条街道，只需要连通城市之间的骨架。

这个组合让 Faiss-IVF-HNSW 成为 SIFT1B、DEEP1B 等十亿级 benchmark 上的经典基线。

2. 算法原理

2.1 IVF 回顾

Inverted File Index 把向量空间聚为 nlist 个 Voronoi 单元。构建时对全部向量做 KMeans，得到 nlist 个质心 c_1..c_nlist；每个点 x 被分配到最近的质心 c_i，形成 posting list。查询时：

  1. 对查询 q，找出最近的 nprobe 个质心（粗量化）
  2. 把这些 posting list 中的点收集起来，做精排

2.2 瓶颈：粗量化 O(nlist × d)

当 nlist 从 1 万增长到 100 万时，"扫描全部质心找 top-nprobe"这一步成为不可忽略的开销。IVF-HNSW 的核心思想就是：把这一步替换为在质心集合上的 HNSW 图搜索，把复杂度从 O(nlist) 降到 O(log nlist)。

2.3 存储压缩：PQ (Product Quantization)

为了让 posting list 里的向量能塞进内存，通常把每个 d 维向量切成 M 段，每段用一个 k-KMeans 码本编码为 log2(k) bit。查询时预计算 M × k 的距离查找表 (ADC, asymmetric distance computation)，每个候选点的距离只需 M 次加法。

直觉 · 为什么用残差 r = x - c 而不是原始 x？

每个桶内的点减去桶质心 c 后，都变成了"相对于桶中心的偏移"，分布集中在 0 附近，方差变小。PQ 训练一个共享码本对所有桶的残差都适用（不再是每个桶各自一个大码本），并且量化误差显著更小 —— 因为在小范围内的相同码字数覆盖更密。

直白类比：把 "北京朝阳区某点的经纬度"（原始 x）换成"距离朝阳区中心 XX 米"（残差 r），后者数值范围小得多，同样精度的量化更容易做。

直觉 · ADC（Asymmetric Distance Computation）为何这么快

"非对称"指查询侧和数据侧用不同精度：

  • 查询侧：q 保持浮点精确，先算好 M × k 的 LUT（LUT[m][j] = q 第 m 段到码字 j 的距离平方）。
  • 数据侧：每个候选点只存 M 个字节的码字 code[m]；估距离时做 Σm LUT[m][code[m]]，即 M 次内存查表 + M 次加法。

这个模式对 SIMD 极度友好：LUT 可以塞进 L1 cache，M 次查表用 AVX2/AVX512 的 vpshufb 指令一次批处理多个候选，是工业界万亿 QPS 检索的基础。

2.4 完整流程伪代码

Build:
  1. 抽样 X_train，KMeans 得到 nlist 个质心 C = {c_1, ..., c_nlist}
  2. 在 C 上构建 HNSW 图 H_c（层数、M_max 等参数独立设置）
  3. 对每个 x ∈ X：
       i* = argmin_i ||x - c_i||   （可用 H_c 加速）
       r  = x - c_{i*}             （residual，残差）
       code = PQ.encode(r)         （M 字节）
       inverted_list[i*].append((id, code))
  4. 训练 PQ 码本时使用残差（对每个 posting 内分布更集中）

Query(q, k):
  1. 用 H_c 在 C 上做 HNSW 搜索，得到最近的 nprobe 个质心
     ids_c = HNSW_search(H_c, q, ef=efSearch, top=nprobe)
  2. cand = []
  3. for each c_i in ids_c:
       q_r = q - c_i                  # 残差查询
       LUT = precompute_LUT(q_r)      # M × k 距离表
       for (id, code) in inverted_list[c_i]:
           d_hat = sum_{m=1..M} LUT[m][code[m]]
           cand.append((id, d_hat))
  4. 返回 cand 中 d_hat 最小的 k 个（可选：再用原始向量做精排 reranking）
关键点：HNSW 用于"选桶"，PQ 用于"桶内快速估距"，两者互补。HNSW 的图规模只有 nlist（几万到百万），PQ 压缩后的 posting 内存开销 = N × M 字节。相比原始向量 N × 4d 节省 ~30 倍。

7. 优缺点 & 适用场景

优势

  • 内存友好：PQ 让 10 亿向量能塞进单机内存
  • 粗量化加速：HNSW 把 O(nlist) 降到 O(log nlist)，nlist 可以做大（如 100 万）从而减小 posting 平均长度
  • 训练成本低：HNSW 只在质心上建，规模远小于 N
  • 成熟：Faiss 的 IndexIVFPQ + HNSWCoarseQuantizer 组合稳定可用

劣势

  • PQ 有损：残差量化误差随 M 增大而减小，但内存也随之增加
  • 参数多：nlist、nprobe、M、k、efSearch、M_HNSW 需要一起调
  • 更新代价高：新增点需要重新分配 posting，聚类中心不能频繁重训
  • reranking 依赖：高召回场景往往还要保留少量原始向量做二次精排

适用场景

  • 大规模（1 亿 - 100 亿）静态或半静态数据集，如图像特征检索、embedding 召回
  • 硬件预算有限：需要单机装下几亿向量的场景（如推荐系统的召回索引）
  • 召回率要求 0.9+ 而非 0.99+：能容忍 PQ 引入的少量误差
调参建议（经验值）：
• nlist ≈ 4·√N ~ 16·√N（例如 1 亿点取 40k~160k）
• nprobe = nlist × 1% ~ 5%
• PQ M = d/2 ~ d，k = 256
• HNSW 用于粗量化时 M=32、efSearch=64 通常足够（因为质心数远小于总数据量）

8. 常见误区 & 下一步学什么

常见误区

  1. HNSW-M 和 PQ-M 不是同一个 M：一个控制图度数，一个控制子向量段数，语义完全不同。调参前先确认在改的是哪一个。
  2. nprobe 大不一定 recall 更高：更多桶意味着更多 PQ 估距，估距误差会引入更多假邻居；到一定阈值后曲线反而平坦甚至下滑。
  3. HNSW 部分构建慢：nlist 达到几十万或百万级时，训练要几十分钟到几小时，不要以为它一定"轻量"。
  4. 残差 PQ 的码本策略：per-bucket 训练精度高但内存大；共享码本便宜但对分布不均的数据集有损。选错影响召回。
