ScaNN — 各向异性量化 (Anisotropic Quantization)

Google Research 2020 提出，在 Ann-Benchmarks 多个数据集上称霸多年的召回引擎。核心思想：量化误差沿"内积敏感方向"投影分解，优先降低会显著影响 top-k 结果的误差分量。

前置（必读）： PQ OPQ IVF-PQ MIPS（最大内积搜索）
前置（推荐）： HNSW Classic LSH
关键术语速查（点击展开）
AH（Asymmetric Hashing，非对称哈希）
ScaNN 用的具体量化方案：实际上就是 4-bit PQ（K=16 每段），查询侧用浮点、数据侧用 4-bit 码字，通过 SIMD 一次批处理多个候选。
anisotropic loss（各向异性损失）
L_ani = η·‖r∥‖² + ‖r⊥‖²。给沿数据方向的"平行误差" r∥ 加权 η，让码本训练时更在意这个方向的误差 —— 而这个方向恰好是最影响内积估计的方向。
MIPS（Maximum Inner Product Search，最大内积搜索）
目标：找 argmax_i ⟨q, x_i⟩，而不是最小欧氏距离。推荐系统、embedding 召回、语义检索都是 MIPS 场景。
Lloyd 迭代
K-Means 的经典训练算法（分配 → 更新中心 → 分配 → ...）。ScaNN 用它的加权版本训练各向异性码本。
leaf（叶子分区）
把整个数据集用 KMeans 分成若干个块，每个块就是一个"叶子"，类似 IVF 的桶。参数：num_leaves。
reordering 精排
AH scoring 给出的是近似分数；对 top-K 候选再用原始 float 向量重算一次内积并排序，可以显著提升召回率。
eccentricity 偏心度
数据分布的长宽比：如果所有点大致沿一根轴排布（偏心度大），各向异性收益就明显；如果是各向同性球状分布，anisotropic 与普通 PQ 差别不大。
partition + scoring 两阶段
ScaNN 查询过程：先在 leaf 中心里选 top-num_leaves_to_search（partition 阶段），再在这些 leaf 内部用 AH 表估算内积（scoring 阶段），可选加 reordering 精排。

  • 演示 B（iso vs aniso 对比）：观察 L2 更差但 IP 更准的反直觉现象（第 4 节）。
  • 演示 C（端到端流程）：partition → scoring → reordering（第 5 节）。
  • 第 6 节（η 扫描）：定量看 η 从 1 到 30，召回率的变化曲线，找到饱和点。
  • 第 7 节（性能对标）：把 ScaNN 放到 Flat / Annoy / IVF-PQ / HNSW 一起比较。

本方案解决了什么问题

痛点
IVF-PQ 已经很快（partition + 4-bit LUT），但召回率上不去：普通 PQ 的量化目标是最小化 L2 误差，跟真实业务目标（内积排序）并不一致。
别人的方案
加大 nprobe（多扫几个桶）或加大 M（子向量段数），能换来更高召回，但延迟也线性劣化；OPQ 用旋转让 PQ 更适合分布，但仍是 L2 目标。
本方案关键 idea
各向异性量化：观察发现内积计算里，"平行方向误差"影响远大于"垂直方向"。让码本主动往正确方向优化：给平行误差乘 η 权重，Lloyd 迭代自然把中心拉到"消除平行误差"的位置。
代价
训练更复杂（加权 Lloyd 而非普通 KMeans）；多一个 η 超参需要调（经验值 1~50）；只在 MIPS/cosine 场景有明显收益，对纯 L2 距离场景收益小。

1. 直观理解 —— 为什么 "各向异性"

传统 KMeans / PQ 的量化目标是各向同性的：最小化 ||x - c||²（欧氏距离），把每个方向的误差视为同等重要。ScaNN 说：不对！在最大内积搜索 (MIPS) 场景下，误差是否"要命"取决于它在数据点方向上的分量。

比喻：假设你正在测量一根从桌子中心指向远方的箭头长度。
• 如果箭头是"朝向摄像机"的方向（平行方向）：一点点长度误差就会让排序完全变化 —— 这个方向的误差会被内积放大。
• 如果误差是"侧向偏移"（垂直方向）：内积对它不敏感（一阶投影为 0）。
所以在 MIPS 里，我们应该像"先坐飞机到目标城市（粗筛 partition），再打精细化的车（重点校正平行方向）"。ScaNN 通过重新加权量化损失，让码本主动往"平行分量正确"的方向去优化。

结果：相同码本大小下，Top-k 内积估计的排序错误率显著降低；相同召回率下，压缩比可以进一步提高。

2. 算法原理

2.1 问题设置

给定数据集 X = {x_i}（都归一化到单位球或非归一化），我们要为每个 x 找一个量化 x̃，使得对任意查询 q，估计 ⟨q, x̃⟩ 与真实 ⟨q, x⟩ 的排序基本一致。

2.2 关键洞察：量化误差的方向分解

记误差向量 r = x - x̃。相对数据向量 x，可以做正交分解：

r = r_∥ + r_⊥
r_∥ = ((r · x̂) x̂) ← 沿 x 方向的分量（平行误差）
r_⊥ = r - r_∥ ← 与 x 垂直的分量（垂直误差）

对查询 q，内积估计误差为 ⟨q, r⟩。假设查询 q 在球面上均匀分布，可以证明：

期望[ ⟨q, r_∥⟩² ] : 期望[ ⟨q, r_⊥⟩² ] = d : 1   (d 是维度)

也就是说，平行误差对内积平方误差的贡献远大于垂直误差。

直觉 · 为什么是 d : 1 的比例（最难的一段）

想象数据向量 x 和它的量化误差 r。r 可以分解成两部分：

  • r∥ = 平行于 x 的分量，是1 维的（只有一个方向：沿 x 的正/负）。
  • r⊥ = 垂直于 x 的分量，是(d−1) 维的（其他所有方向）。

当查询 q 在球面均匀分布时，⟨q, r⟩ 的方差主要贡献来自 r∥ —— 因为 r∥ 每次都会对内积产生"同向影响"（它就是沿着 x 的方向，而查询在 top-k 场景下大概率也是"和 x 相近的方向"）。而 r⊥ 的贡献在多个维度平均后趋近 0（有正有负相互抵消）。

粗略讲，⟨q, r∥⟩² 的期望大约是 ⟨q, r⊥⟩² 期望的 d 倍。所以在 d=100 的场景下，1 单位的平行误差 ≈ 100 单位垂直误差的影响。

但这只是"如果 q 随机均匀"的情况。ScaNN 进一步注意到：Top-k 时更容易 rank 出错的是"内积大"的那些 x——它们代表 q 大概率是"和 x 接近同向"的方向。因此对 Top-k 场景，平行误差比垂直误差的重要性甚至更悬殊。

2.3 各向异性损失函数

L_aniso(x, x̃; η) = η · ||r_∥||² + ||r_⊥||²

其中 η = h_parallel / h_perpendicular ≥ 1：

  • η = 1：等价于普通欧氏距离 (isotropic)，退化成标准 PQ / KMeans
  • η → ∞：只关心平行方向的误差
  • 论文经验：η 取 1~50，具体依赖 Top-k、数据分布

码本 C = {c_j} 通过最小化整体损失得到 —— 这仍然可以用类 Lloyd 算法迭代求解（每步是加权最小二乘）。

直觉 · L_ani = η·‖r∥‖² + ‖r⊥‖² 到底做了什么

给平行方向误差加权 η（大于 1），意思是"平行误差比垂直误差重要 η 倍"。Lloyd 迭代重新算中心时会把中心往"消除平行误差"的方向拉：

  • η 越大 → 中心越贴近"数据点方向的延长线"上 → 内积估计越准（因为 r∥ 更接近 0）。
  • 副作用：中心不再是几何"平均位置"，L2 距离 反而变差（对 L2 场景不利，但 MIPS 场景恰好想要）。

类比：普通 KMeans 是"找到一个位置让所有人到我这里的路程之和最小"；anisotropic 是"找到一个位置让所有人和我'投影到主方向上的偏差'加权最小"—— 后者会把中心往主轴的方向"拉紧"。

直觉 · AH 就是 4-bit PQ

AH (Asymmetric Hashing) 听起来玄乎，实际上就是 K = 16（4 bit）的 PQ：每段子向量只有 16 个码字，一个字节能存两段。

为什么选 4 bit 而不是 PQ 常用的 8 bit（K = 256）？因为 SIMD AVX2 的 vpshufb 指令可以把一张 16 项的表塞进一个 128-bit 寄存器，然后一次性算 16 个候选的距离 —— 这是 4-bit 独有的硬件红利。ScaNN 的高 QPS 很大一部分靠这个。

2.4 完整 ScaNN 索引流程

Build:
  1. Partitioning：对 X 做球形 KMeans 得到 num_leaves 个分区（类似 IVF）
  2. Scoring：对每个分区内的向量做 anisotropic quantization
       - AH (Asymmetric Hashing): x → 4-bit code per subvector
       - 训练码本时用 L_aniso 而非 L2
  3. 可选 Reordering：保留少量原始 float 向量做二次精排

Query(q, top_k):
  1. Partition search:
       对 num_leaves 个中心算 ⟨q, c_i⟩，取 top-num_leaves_to_search
  2. Scoring:
       对候选点用 AH 表估 ⟨q, x̃⟩（LUT 查表，加法即可）
       取 top-reorder_candidates
  3. Reorder (optional):
       用原始 float 向量对候选精排，取 top-k

2.5 与其它方案的对比

• IVF-PQ → partitioning + isotropic quantization
• ScaNN → partitioning + anisotropic quantization + reordering
• FAISS-HNSW → graph traversal，不做 quantization

ScaNN 的杀手锏是"用同样的字节数得到更精确的内积估计"。在 GloVe100 (100 万点) 上，同等 recall 下比传统 IVF-PQ 快 2~4×。

8. 优缺点 & 适用场景

优势

  • 相同码本大小下更高召回：anisotropic 损失明确对齐 MIPS 目标
  • SIMD 友好：4-bit AH 表 + AVX2/AVX512 打表指令，单机 QPS 极高
  • 灵活：η 可调，可退化到普通 PQ 作为消融基线
  • 开源 google-research/scann，支持 GPU 与 TF 集成

劣势

  • 参数复杂：η、num_leaves、num_leaves_to_search、reorder_k、AH bits 都要调
  • 更适合 MIPS/余弦：欧氏距离下优势相对不明显
  • 训练比 Faiss 慢（anisotropic Lloyd 需加权求解），大规模建索引时间 x2 常见
  • 动态更新不友好（同 IVF 类方法）

适用场景

  • 大规模 embedding 检索（推荐/广告召回、语义搜索）
  • MIPS / 余弦相似度为主要度量的场景
  • 对 QPS 有严苛要求，且能接受 recall 0.9~0.98 之间
  • 能忍受较长离线索引构建时间的批量服务

9. 常见误区 & 下一步学什么

常见误区

  1. anisotropic ≠ "更精确的 PQ"：它优化的是内积估计，L2 误差可能反而增大。别拿 L2 指标去看 aniso 码本，会被误导。
  2. η 不是越大越好：超过某个阈值（依数据分布，常见 20~50 之间）后，中心过度贴向数据方向，反而使召回下降。看第 6 节的扫描曲线找拐点。
  3. 只在 MIPS / cosine 场景有明显收益：如果你的相似度是 L2 欧氏距离，收益微弱，甚至不如 OPQ。
  4. 需要配合 reordering 才能达到最佳召回：AH 只保证 top-K 候选大概率包含真答案，最终排序还要用原始向量精排一次。

下一步学什么

  • 想了解 Google 内部对这套技术的进一步演化：SOAR（NeurIPS 2023）、以及 google-research/scann 仓库里的 TF/GPU 集成。
  • 横向对标另一个工业界方案：IVF-HNSW（本目录） —— 同样是 partition + PQ 但用 HNSW 加速粗量化、用 residual + 8-bit PQ 而非 4-bit AH，可以对比两者选型时的取舍。
