KD-Tree · K 维空间划分树

Bentley 1975 提出的多维二叉搜索树。用轴对齐超平面递归切分空间，通过回溯与剪枝加速最近邻搜索。
前置阅读： 无（本类别入门算法） 建议：了解二叉搜索树 BST 与递归 返回总览
重要说明： KD-Tree 本质上是精确 K-NN 结构（低维下），不是近似方法。它被放在 ANN 教程里作为"树类"入门；进入 ANN 语义的近似变体是 Best-Bin-First（Beis & Lowe 1997）与 Annoy。
关键术语速查（点击展开/收起）
轴对齐分割（axis-aligned split）
沿某一个坐标轴（如 x 轴或 y 轴）切一刀把空间分成两半——想象用"东西方向"或"南北方向"的直线切地图。KD-Tree 的所有分割都是轴对齐的，这也是它跟 Ball Tree 最本质的区别。
切分维度（split dimension） / 切分阈值（split value）
每个内部节点存一对 (d, t)：d 说"在哪一维上切"，t 说"切在哪个位置"。Bentley 原始版本 d = depth mod k，即按深度轮转；实践中常改为方差最大或范围最大的维度。
中位数分裂
把点按当前维度排序，取正中间那个点作为切分点。左右两边点数几乎相等，保证树平衡、深度 O(log N)。
回溯（backtracking）
先递归下降到最可能的叶子，再一路返回父节点。返回时顺便检查"另一侧子树"里有没有可能藏着更近的点。
剪枝（pruning）
发现某个子树里的所有点都不可能比当前最优更近，直接跳过、不进入。剪枝越强、访问节点越少——这是 KD-Tree 相对暴力扫描的加速来源。
轴距离（splitting-plane distance）
查询点到切分超平面的垂直距离：|target[d] − pivot[d]|。它是另一侧子树内任何点到查询点距离的下界——如果这个下界已经不小于当前最优半径，就可以整个子树剪掉。
维度诅咒（curse of dimensionality）
高维空间（> 20 维）中任意两点的距离几乎都相等，切分超平面近乎失去区分度，剪枝条件几乎永远不成立，KD-Tree 退化为暴力扫描（Weber, Schek & Blott 1998 有严格分析）。
叶子容量（leaf size）
不再往下切分的阈值。子集大小小于该值时直接存点数组、逐个算距离。太小导致树太深，太大导致叶内暴力扫描代价上升；sklearn 默认 30。
Best Bin First (BBF)
Beis & Lowe (1997) 提出的 KD-Tree 近似查询：把待访问的子树放进优先队列（按到查询点的距离），只查前 emax 个叶子。SIFT 图像匹配的经典配套算法。

1. 直观理解与历史背景

1.1 从"二叉搜索树"到"K 维搜索树"

普通的二叉搜索树（BST）能在一维数字里做 O(log N) 查找："比根小走左边、比根大走右边"。 但当"键"变成 2 维、3 维甚至 128 维向量时，BST 就不够用了——因为没法定义"整体上更大还是更小"。

Jon Louis Bentley 在 1975 年（论文 "Multidimensional Binary Search Trees Used for Associative Searching", Communications of the ACM, 18(9)）给出了一个优雅的解法：每一层只在一个维度上比较。 第 0 层用 x 轴切、第 1 层用 y 轴切、第 2 层再回到 x 轴……如此轮换。这样每个内部节点只做"一维比较"， 但整棵树共同覆盖了所有 k 个维度。

1.2 生活化类比

想象你在一张巨大的城市地图上要找 离你家最近的便利店。若逐个计算距离，需要访问全部便利店； 但你可以先按城市 东经/西经 二分：目标店铺一定在你所在的东半区或西半区之一； 接着在该半区再按 南北纬度 二分；如此反复，快速缩小搜索范围。

关键的教学要点：找到一个"候选便利店"后，你不能马上停——还需要检查"我到区界的垂直距离"是否比"我到候选店的距离"更小。 若前者更小，另一半区可能藏着更近的店，必须去看；若前者更大，另一半区整体跳过。 这就是回溯 + 剪枝，是 KD-Tree 快过暴力扫描的根本原因。

核心直觉一句话

KD-Tree = 轴对齐超矩形 的空间划分。查询下降时只用一维比较，回溯时用"查询点到分割线的垂直距离"作为 整个子树最近点距离的下界，用这个下界与"当前最优距离"比较来决定是否剪枝。

1.3 KD-Tree 在 ANN 生态中的位置

  • 低维（k ≤ 10）：KD-Tree 是精确 K-NN 的黄金选择，实测查询复杂度 ≈ O(log N)。sklearn NearestNeighbors 默认在 k ≤ 15 时启用。
  • 中等维度（10 < k < 20）：性能开始退化，比 Ball Tree 略弱。
  • 高维（k ≥ 20）：几乎失效——Weber, Schek & Blott（VLDB 1998）证明"当维度足够高时，所有基于空间划分的方法都不比顺序扫描更好"。此时必须用近似方法：LSH、Annoy、HNSW、IVF-PQ 等。
  • ANN 变体：Beis & Lowe（CVPR 1997）提出的 Best-Bin-First (BBF) 把"完备回溯"改为"优先队列 + 只查前 emax 个叶子"，牺牲精确性换速度，是 SIFT 图像匹配的经典配套。Annoy 则用随机投影超平面代替轴对齐，是同类思路的现代化。

2. 算法原理（Bentley 1975 严格定义）

2.1 数学定义

直觉铺垫：每个点是一组 k 个数字，例如 2 维时 (经度, 纬度)，3 维时 (R, G, B)。 下面公式里的 xd 就是"取这个点在第 d 个数字的值"；xd ≤ t 相当于问"这个点在 d 轴上是否位于阈值 t 的左边"。

给定点集 P = {p1, p2, …, pn} ⊂ ℝk。 KD-Tree 是一棵二叉树，每个内部节点存三样东西：

  • 切分点 p ∈ P——通常也是数据集里真实存在的一个点（Bentley 原论文的做法；也有变体把切分点存成"虚拟中位数"，如 Friedman/Bentley/Finkel 1977 的改良版）。
  • 切分维度 d ∈ {0, 1, …, k−1}——决定"在哪一维上比较"。
  • 切分阈值 t = pd——就是切分点在维度 d 上的坐标。

该节点把 k 维空间划分成两个半空间：

左子树覆盖: { x ∈ ℝk : xd ≤ t }
右子树覆盖: { x ∈ ℝk : xd > t }

叶子节点：当子集大小 ≤ leaf_size 时不再切分，直接把这几个点存成数组，查询时暴力扫。

2.2 三种切分维度选择策略

策略做法出处 / 用途
轮转（cyclic） d = depth mod k：第 0 层切 x，第 1 层切 y，…… Bentley 1975 原始版本；实现最简单
最大方差（max variance） 选当前子集里方差最大（数据最"散"）的那一维 Friedman-Bentley-Finkel 1977；剪枝更有效，构建略慢
最大范围（max spread） 选 max(coord) − min(coord) 最大的那一维 sklearn KDTree 默认；比方差计算便宜、效果相近

2.3 构建流程（Bentley 1975 伪代码）

直觉铺垫：下面 axis = depth % k 是轮转策略。以 2 维为例：depth=0 用 x 轴切，depth=1 用 y 轴切，depth=2 又回到 x 轴，如此往复。取中位数作切分点是为了保证左右子集大小相等，树深 O(log N)。 
def build_kdtree(points, depth=0):
    if not points:
        return None
    if len(points) <= leaf_size:            # 叶子节点，存点数组
        return Leaf(points=points)

    k = len(points[0])
    axis = depth % k                              # 轮转策略：depth=0→x, depth=1→y
    points.sort(key=lambda p: p[axis])
    median = len(points) // 2

    return Node(
        point = points[median],
        axis  = axis,
        left  = build_kdtree(points[:median], depth+1),
        right = build_kdtree(points[median+1:], depth+1),
    )

2.4 最近邻查询：先下降、再回溯、途中剪枝

直觉铺垫：查询分两步——(1) 像玩"猜数字"一样一路向下走到"最像"目标的叶子，记住当前最近距离； (2) 往回走时，对每个岔口检查：另一侧最少需要多远才能到？ 如果这个下界都比现在的最优距离大，另一侧整块跳过。这就是回溯 + 剪枝。 
def nn(node, target, best=None):
    # best = 当前找到的最近邻 {point, dist}；None 表示尚未找到（半径=∞）
    if node is None: return best

    # --- 步骤 1：先在当前节点更新 best ---
    d = dist(node.point, target)
    if best is None or d < best.dist:
        best = Best(point=node.point, dist=d)

    # --- 步骤 2：先递归"更可能"的一侧（near）---
    diff = target[node.axis] - node.point[node.axis]
    near, far = (node.left, node.right) if diff < 0 else (node.right, node.left)
    best = nn(near, target, best)

    # --- 步骤 3：回溯时检查 far 是否需要进入（剪枝判定）---
    #     轴距离 |diff| 是 far 子树内任何点到 target 距离的下界
    if abs(diff) < best.dist:
        best = nn(far, target, best)         # 下界仍可能突破 → 递归
    # else: |diff| ≥ best.dist → 整棵 far 子树剪掉
    return best

2.5 剪枝的几何证明（关键！）

为什么"轴距离 ≥ 当前最优"就能剪掉整棵子树？这里给出严格证明。

设当前节点切分维度为 d、切分阈值为 t；far 子树覆盖的空间是 {x : xd > t}（假设 target 在左侧，对称情形同理）。

对任意 x ∈ far 子树，有 xd > t ≥ targetd（因为 target 在左侧意味着 targetd ≤ t）。于是：

‖x − target‖2 ≥ |xd − targetd| ≥ |t − targetd| = |diff|

换句话说，|diff| 是 far 子树内任何点到 target 的欧氏距离的下界。所以只要 |diff| ≥ best.dist，那 far 子树里就绝不可能有比 best 更近的点，可以整块跳过。

剪枝条件的口诀

「查询点到切分线的垂直距离 ≥ 当前最优半径」→ 整棵远侧子树剪掉。
在下面第 4 节的动画中，你会亲眼看到"红色斜纹遮罩"覆盖被剪枝的整块空间。

2.6 K 近邻查询（K > 1）

把 best 从"单个最优"改成"大小为 K 的最大堆"（堆顶是当前 K 近邻里最远的那个）：

  • 访问一个点时，若堆未满或 d < heap.top()，则 push（挤掉最远的一个）。
  • 剪枝条件从 |diff| < best.dist 改为 |diff| < heap.top()（用当前"第 K 近的距离"作半径）。

本页的 knnSearch 实现就采用了这个最大堆策略（K ≤ 5 时用数组模拟即可）。

7. 优缺点 & 适用场景

    

        

            
优点

            
    
                
  • 低维（≤ 10 维）下极其高效，实测 O(log N)。
    • 
                
  • 结构简单、实现门槛低，是学习空间索引的最佳入门。
    • 
                
  • 支持精确 K 近邻查询，不是近似。
    • 
                
  • 可扩展到范围查询（range query）、区间查询等多种几何操作。
    • 
                
  • 用途极广：GIS、机器人碰撞检测、密度估计（sklearn KernelDensity 底层就是 KD-Tree）。
    • 
            

        

        

            
缺点

            
    
                
  • 维度诅咒：k ≥ 20 时几乎退化为暴力扫描。
    • 
                
  • 只适用于欧氏或 Lp 距离（几何证明依赖轴距离下界）；不能直接用于余弦、编辑距离等。
    • 
                
  • 动态插入不会自动 rebalance，写入密集场景不友好。
    • 
                
  • 不支持磁盘外存友好访问（每个节点大小固定但访问模式随机）。
    • 
                
  • 切分点必须存在数据集中（Bentley 版本）→ 稀疏区域的切分可能极不均衡。
    • 
            

        

    


    
典型工程场景

    
    
        
  • 2D / 3D 地理坐标最近邻：例如"找我附近的餐厅"、"最近的基站"。PostGIS 的 <-> 运算符底层可用 KD-Tree。
    • 
        
  • 机器人碰撞检测 / 运动规划：RRT (Rapidly-exploring Random Tree) 算法在采样后需要频繁最近邻查询，KD-Tree 是标配。
    • 
        
  • 密度估计 & 聚类：sklearn 的 DBSCAN、KernelDensity、NearestNeighbors（默认 kd_tree）在 k < 15 时全部使用 KD-Tree。
    • 
        
  • 三角网格 / 点云处理：Open3D 的 KDTreeFlann 用于 3D 点云去噪、法线估计。
    • 
        
  • SIFT 图像匹配的近似加速：Beis & Lowe (1997) 的 BBF (Best-Bin-First) 变体使 KD-Tree 在 128 维 SIFT 特征上仍能用；OpenCV FlannBasedMatcher 默认底层。
    • 
    






    
8. 代码调用示例


    
scikit-learn（Python，最常用）

    
from sklearn.neighbors import KDTree
import numpy as np

X = np.random.rand(1000, 3)         # 1000 个 3 维点
tree = KDTree(X, leaf_size=30, metric='euclidean')

query = np.random.rand(1, 3)
dist, ind = tree.query(query, k=5)      # 返回 5 近邻
print(dist, ind)


    
SciPy（C 实现，更快）

    
from scipy.spatial import cKDTree
tree = cKDTree(X)
dist, ind = tree.query(query, k=5)

9. 常见误区

    

        
初学者容易踩的四个坑

        
    
            
  1. 把 KD-Tree 用在几百维的 embedding 上——错。 维度诅咒（Weber-Schek-Blott 1998 有严格证明）会让剪枝失效，你会以为算法很快，其实退化到 O(N)。BERT-768 / OpenAI-1536 请直接用 HNSW / IVF-PQ / ScaNN，不要用 KD-Tree。
    2. 
            
  2. 用平均值代替中位数——错。 一旦数据有偏态分布（例如长尾），平均值切分会让一侧长期很大另一侧很小，树严重失衡；查询最坏 O(N)。始终按当前维度中位数切分。
    3. 
            
  3. 把切分点存进数据但不明白切分点也参与比较——错。 Bentley 原版切分点也是数据点，查询时必须先在这个点上算距离、再决定走近侧或远侧。有些教材伪代码把切分点写成"虚拟阈值"（如 sklearn），需要理解两种约定的差异。
    4. 
            
  4. 频繁增删数据不重建——错。 KD-Tree 是静态平衡结构；插入不会自动 rebalance。写入密集场景请周期性完全重建，或改用支持增量更新的 HNSW。
    5. 
        

    






    
10. 下一步学什么

    

        
推荐路径：当维度增加到十几或几十维，KD-Tree 的"长条盒子"很难剪枝，此时应该学习用超球体替代超矩形的方案，或者放弃精确性换速度。

        
    
            
  • 下一站：Ball Tree / VP-Tree——用球代替盒子，剪枝依赖三角不等式，可以处理中等维度和任意度量空间。
    • 
            
  • 近似加速：Best-Bin-First (BBF)——把回溯改为优先队列 + 只查前 emax 叶子，牺牲少量精度换速度（OpenCV FLANN 默认）。
    • 
            
  • 再进阶：Annoy 随机投影树森林——放弃轴对齐、改用随机超平面切分并集成多棵树。
    • 
            
  • 大规模现代方案：HNSW（分层小世界图）、IVF-PQ（倒排 + 乘积量化）、ScaNN（各向异性量化），可以处理亿级 embedding 检索。
