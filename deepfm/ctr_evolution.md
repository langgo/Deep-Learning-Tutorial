## Part I. DeepFM 之前：从线性模型到"宽深融合" (2010–2016)

### 1.1 广义线性模型时代（~2013）

**代表**：LR + FTRL (McMahan et al., 2013, Google)

- 每个特征一个权重 $w_i$，$\hat{y} = \sigma(\sum w_i x_i)$
- 优点：训练快、可解释、易在线更新
- **致命短板**：无法学特征交互；工业上只能靠**人工构造交叉特征**（gender × age、user_id × app_id 等）
- 人工交叉的三大问题：
  1. 依赖领域经验，难穷尽
  2. 稀疏交叉特征在训练集里几乎不出现，学不到有效权重
  3. 特征数量组合爆炸，工程成本高

### 1.2 因子分解机时代（2010–2015）

**代表**：FM (Rendle, ICDM 2010) → FFM (Juan et al., 2016)

**FM 的核心突破**：把两两特征交互建模为潜在向量的内积——

$$y_{FM} = \langle w, x\rangle + \sum_{i<j} \langle V_i, V_j\rangle x_i x_j$$

**关键洞察**：交互参数不再是独立的 $O(d^2)$ 个标量，而是由 $d \times k$ 个潜在向量参数**内积生成**。

带来的好处：
- **稀疏泛化**：即使特征 $i$ 和 $j$ 在训练集里从未共现，只要各自出现过，$V_i$、$V_j$ 就都能学到，内积依然有意义
- 参数量从 $O(d^2)$ 降到 $O(dk)$
- 利用平方差恒等式，二阶计算可从 $O(d^2 k)$ 降到 $O(dk)$

**FFM (Field-aware FM)**：让特征在不同 field 上下文里有不同的 $V$，进一步细化：$V_i^{(f)}$ 表示"特征 $i$ 与 field $f$ 交互时的潜在向量"。表达力更强，但参数量翻 $m$ 倍（$m$ 为 field 数）。

**FM 系列的天花板**：原则上可以做高阶交互（$\sum_{i<j<k}\langle V_i, V_j, V_k\rangle$），但复杂度炸裂，实践中只做二阶。

### 1.3 深度学习入场（2015–2016）

DNN 天生擅长学习高阶非线性组合，但直接用于 CTR 有两个障碍：
1. 输入是**高度稀疏**的 one-hot（十亿用户 ID 一个 field 就十亿维），MLP 第一层参数会爆炸
2. 稀疏 one-hot 直接进 MLP，梯度极其稀疏，网络难以训练

**关键突破**：**Embedding 层**——把每个 field 的 one-hot 压缩成 $k$ 维稠密向量，再送入 MLP。

**代表**：
- **FNN** (Zhang et al., ECIR 2016)：用 FM 预训练 embedding，再喂给 DNN。缺点：两阶段训练效率低、只学高阶交互、丢失低阶信息
- **PNN** (Qu et al., ICDM 2016)：在 embedding 层与 MLP 之间加 product 层（内积 IPNN / 外积 OPNN / 双 PNN\*）。缺点：外积近似不稳定；product 层输出连到 MLP 所有神经元，计算量大；同样忽略低阶

### 1.4 融合尝试：Wide & Deep (2016, Google)

**关键动机**：低阶交互（记忆能力，wide）和高阶交互（泛化能力，deep）都重要，应同时建模。

**架构**：
- **Wide 部分**：LR + 人工交叉特征
- **Deep 部分**：Embedding + MLP
- 两路输出相加过 sigmoid，联合训练

**残留问题**：
- Wide 部分仍然需要**专家特征工程**（哪些交叉要人工设计）
- Wide 和 Deep 的输入是分离的，参数不共享，训练时不能相互促进

## Part II. DeepFM：三条问题的一次性收敛 (2017)

Guo et al. (华为诺亚 + 哈工大, IJCAI 2017) 提出 DeepFM，**三个设计同时解决三个前人问题**：

| 前人问题 | DeepFM 解法 |
|---|---|
| Wide & Deep 的 wide 部分需要人工交叉特征 | 用 **FM** 替代 wide 部分，自动学二阶交互 |
| FNN 的 FM 预训练拖累效率 | FM 和 DNN **联合训练**，端到端 |
| Wide & Deep 中两路输入分离，参数不能互促 | FM 和 DNN **共享同一份 embedding $V$**，两路梯度共同塑造特征表示 |

DeepFM 由此成为"低阶 + 高阶 + 共享表示 + 免特征工程"这一范式的**奠基性工作**，其架构骨架被后续绝大多数 CTR 模型继承。

**架构式**：$\hat{y} = \text{sigmoid}(y_{FM} + y_{DNN})$

<a id="part-iii"></a>
## Part III. DeepFM 之后：五条正交演化路线 (2017–2024)

DeepFM 的成功不是终点。它遗留了 5 类问题，每类衍生出一条独立的技术路线。理解这五条路线的**动机**比记住模型名字重要得多。

---

### 路线 1：显式高阶交互

**DeepFM 的遗留问题**：Deep 部分是黑盒 MLP，虽然理论上能学任意高阶交互，但过程不透明、不可控、不可解释。FM 部分则只学二阶。**能不能让"高阶交互"变成显式、可控、有明确阶数的计算？**

| 模型 | 年份 | 核心思想 | 相对进步 |
|---|---|---|---|
| **DCN** (Deep & Cross Network) | 2017 | Cross Network 递归 $x_{l+1} = x_0 x_l^\top w_l + b_l + x_l$ | 每层显式做一次特征交叉，L 层表达 L+1 阶交互，参数量线性 |
| **xDeepFM** | 2018 | CIN (Compressed Interaction Network) | **vector-wise** 显式高阶交互（DeepFM 是 bit-wise），保持 field 语义 |
| **AutoInt** | 2019 | Multi-head self-attention 学特征交互权重 | 交互重要性**可学、可解释**；对齐 Transformer 范式 |
| **FiBiNET** | 2019 | SENet 学 field 重要性 + bilinear 交互 | 显式建模 field 间不对称交互 |
| **DCN-V2** | 2020 | 把 DCN 的 Cross 升级为矩阵形式 $x_{l+1} = x_0 \odot (W_l x_l + b_l) + x_l$ | Google 内部实测超 DCN/DeepFM/xDeepFM，工业落地首选 |

**核心洞察**：DeepFM 的两分支设计是"低阶 vs 高阶"的二分法。这条路线把二分法细化为**逐阶显式建模**，让模型能力可控且可诊断。

---

### 路线 2：用户行为序列建模

**DeepFM 的遗留问题**：DeepFM 把用户当作一堆静态 field（性别、年龄、注册城市……），**完全忽略了用户行为的时间序列**。但真实场景里，"用户是谁"往往更取决于"用户最近做了什么"。

| 模型 | 年份 | 核心思想 |
|---|---|---|
| **DIN** (Deep Interest Network, 阿里) | 2018 | 用 **target attention** 从用户历史行为里挑出与候选物品相关的部分 |
| **DIEN** (Deep Interest Evolution) | 2019 | DIN + GRU + AUGRU，建模兴趣**演化**过程 |
| **BST** (Behavior Sequence Transformer, 阿里) | 2019 | 用 Transformer 替代 GRU 建模行为序列 |
| **MIMN** (Multi-channel Interest Memory Network, 阿里) | 2019 | 用 memory network 处理长序列（千级别） |
| **SIM** (Search-based Interest Model, 阿里) | 2020 | 长序列（万级别）用两阶段检索 + attention |
| **ETA / SDIM / TWIN** | 2021–2023 | 长序列高效检索的进一步优化（LSH / SimHash / 双塔检索） |

**核心洞察**：用户是一个**动态过程**而非静态特征集合。这条路线的关键技术是各种形式的 **attention**：让模型自己决定"看历史中的哪一段"。

**副产物**：把 NLP 里的 Transformer / attention 机制系统性引入到推荐排序，为后来的"推荐大模型"打下基础。

---

### 路线 3：多任务与多场景

**DeepFM 的遗留问题**：DeepFM 只优化单一二分类目标（点击/不点击）。但工业推荐系统需要同时预估**点击、转化、时长、完播、加购、分享……**多个目标；且要在**首页、搜索、详情页、Push**多个场景下工作。独立训一堆模型显然浪费信息、样本效率低。

| 模型 | 年份 | 核心思想 |
|---|---|---|
| **ESMM** (Entire Space Multi-Task, 阿里) | 2018 | 用 $pCTR \times pCVR = pCTCVR$ 解决 CVR 训练的**样本选择偏差** |
| **MMoE** (Multi-gate Mixture-of-Experts, Google) | 2018 | 多个 expert + 每任务一个 gate，任务间的**共享/分化程度可学** |
| **PLE** (Progressive Layered Extraction, 腾讯) | 2020 | 把 MMoE 的 expert 分成"任务专属"和"共享"两组，缓解**跷跷板效应** |
| **STAR** (Star Topology, 阿里) | 2021 | 多场景共享**中心网络** + 场景专属参数 |
| **ESCM² / DCMT** | 2022+ | 用因果推断视角进一步纠偏 |

**核心洞察**：多目标之间存在**信息互补**（点击是转化的前提，观看是完播的前提）。这条路线的核心是设计**参数共享结构**，让模型自动学到"哪些底层特征在任务间可共享、哪些必须分化"。

---

### 路线 4：召回与双塔

**DeepFM 的遗留问题**：DeepFM 前向计算里用户和物品特征**深度耦合**（拼进同一个 MLP），每次打分需完整前向。系统召回阶段面对**百万级候选**时，DeepFM 类模型算力上根本跑不动。

| 模型 | 年份 | 核心思想 |
|---|---|---|
| **YouTubeDNN** (Google) | 2016 | 用户塔 + 物品塔，最终 embedding 内积/余弦，**物品塔离线预算 + ANN 检索** |
| **DSSM** 系列 | 各年 | 双塔的通用范式：语义匹配 + 内积打分 |
| **SENet 双塔 / COLD** (阿里) | 2020 | 粗排的复杂度与效果权衡 |
| **TDM / JTM / DR** (阿里) | 2018–2020 | **树结构 / 深度树**，突破双塔"最后一层内积"的表达瓶颈 |
| **MIND / ComiRec** | 2019–2020 | 用户**多兴趣向量**（一个用户 → 多个 embedding） |

**核心洞察**：召回和排序有本质不同的算力约束。这条路线用**信息瓶颈换算力**：牺牲用户-物品耦合，换来物品向量可离线预算、亿级候选毫秒检索。

---

### 路线 5：Scaling Law 与生成式推荐

**DeepFM 的遗留问题**（更宏观）：CTR 领域长期存在一个"魔咒"——模型参数量增大**没有明显收益**，甚至更差。这与 NLP/CV 的 scaling law 形成鲜明对比。这背后的问题是：**推荐模型的架构是否有根本瓶颈？能否用更大规模的算力换更好的效果？**

2023 年后，这个问题被重新审视，出现了几个关键工作：

| 方向 | 代表 |
|---|---|
| **推荐 Scaling Law 探索** | **HSTU** (Meta, 2024, 万亿次训练算力)、**HLLM** (字节, 2024)、**Wukong** (Google, 2024) —— 证明推荐模型架构合适时**存在 scaling law**，可放大到十亿/百亿参数持续有收益 |
| **生成式推荐** | 把推荐建模成 next-item generation（类 GPT）：**TIGER** (2023)、**P5**、Meta 的 **GR** |
| **LLM 融合推荐** | LLM 作为 reranker、用户/物品 embedding 生成器、或直接冷启动辅助模型 |
| **统一模型** | 用一个基座模型同时做召回 / 粗排 / 精排 / 重排（工业界正在探索） |

**核心洞察**：过去 10 年推荐领域的主流是**手工设计小模型 + 特征工程**（DeepFM 就是典型代表）。2024 起主流转向**基座模型 + 数据规模**的范式转型，与 NLP/CV 走过的路一致。这是一场正在发生的**技术革命**，其终局尚未清晰。

## Part V. 阅读建议

### 如果你是初学者
先吃透**三个基础模型**——它们代表三个思想跃迁：
1. **FM** — 稀疏数据下的参数共享
2. **Wide & Deep** — 低阶 + 高阶融合
3. **DeepFM** — 端到端共享表示

### 如果你要做工业级推荐系统
必读**三个方向的代表**：
1. **DCN-V2**（排序，替代 DeepFM）
2. **DIN / SIM**（用户序列建模）
3. **MMoE / PLE**（多任务）

再加上一个双塔召回模型（YouTubeDNN 或 MIND），你就有了一个现代推荐系统的完整认知骨架。

### 如果你要跟前沿研究
关注 2023 年后：
- **HSTU** (Meta) — 推荐 scaling law 的第一份严肃证据
- **TIGER** — 生成式推荐的雏形
- **RecSys / KDD / SIGIR** 每年的 best paper

### 快速评估一个新模型的价值

问自己三个问题：
1. 它**解决了哪一代模型的什么局限**？（如果说不清，多半是灌水）
2. 它引入了多少**新的信息**（新特征、新数据源、新监督信号）？还是只是换了个架构？
3. 它在**工业规模数据**上有验证吗？还是仅在 Criteo 这类玩具数据集上有几个千分点提升？

## 附录：五条演化路线的正交性总结

DeepFM 的五个后继方向**不是相互替代**，而是**正交演化**——现代推荐系统通常同时使用其中多条路线的技术：

| 路线 | 解决什么维度的问题 | 现代代表 | 是否与 DeepFM 兼容 |
|---|---|---|---|
| 1. 显式高阶交互 | 特征交叉的表达力 | DCN-V2 | 直接替换 DeepFM 中的 Deep 部分 |
| 2. 序列建模 | 时间维度 | DIN / SIM | 作为一个 field 输出接入 DeepFM |
| 3. 多任务 | 多目标监督 | MMoE / PLE | 把 DeepFM 作为共享底座 |
| 4. 召回 | 算力约束 | 双塔 / TDM | 与 DeepFM 分工（召回 vs 排序） |
| 5. Scaling / 生成式 | 范式革命 | HSTU / TIGER | 可能整体替代 DeepFM 类小模型 |

一个典型工业推荐系统的模块化视图：

```
┌──────────────┐    ┌──────────────┐    ┌───────────────┐    ┌─────────────┐
│   召回        │    │   粗排        │    │   精排         │    │   重排       │
│  双塔 / TDM   │ →  │  轻量 DNN     │ →  │ DCN-V2 + DIN   │ →  │  多样性 / 业务│
│  (路线 4)     │    │              │    │  + MMoE 多任务  │    │  规则        │
│              │    │              │    │  (路线 1+2+3)   │    │              │
└──────────────┘    └──────────────┘    └───────────────┘    └─────────────┘
   百万→千级          千→百级            百→几十级             几十→展示
```

DeepFM 在这张图里已不是主角，但它奠定的"共享 embedding + 双分支融合"范式仍无处不在——这是一个"经典模型"的最高褒奖：它的思想成了空气。
